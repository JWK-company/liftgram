# 와이어프레임 만들기 가이드 (사용자 흐름)

> Claude Code + PLM으로 **기획 → 와이어프레임 → 피드백**을 잇는 실사용 흐름. 화면 수 제한 없음(이 제품에 필요한 만큼).
> 관련: `_WIREFRAME-SAE-METHODOLOGY.md`(SAE 표기법) · `commands/wfgen.md`(생성기) · `commands/wfscan.md`(아티팩트 발급).

---

## 0. 한눈에 — 3단계 루프

```
① 기획      /business·/plan(·/requirement)로 BS·Roadmap(·요구) 생성 → 검토
              ↓
② 생성 지시  와이어프레임 탭 채팅에 "와이어프레임 만들어줘"
              → (Claude가) 계획에서 화면 도출 → 화면마다 SAE 스펙 저작 → 생성 → 아티팩트 발급 → 렌더 검증
              ↓
③ 피드백     penpot 미리보기를 보며 "이 화면 이렇게 바꿔/화면 추가" → 재생성 → 재렌더  ⟲ 반복
```

핵심: **화면은 이 제품의 계획(BS/Roadmap/요구)에서 나온다.** 고정 샘플(3장) 없음 — 3개든 12개든 필요한 만큼.

---

## 1단계 — 기획: BS·Roadmap(·요구) 생성 후 검토

와이어프레임은 "무엇을 만들지"가 정해진 뒤에 그린다. 먼저 기획 문서를 만들고 검토한다.

| 순서 | 스킬 | 산출 | 검토 포인트 |
|------|------|------|-------------|
| 1 | `/business` | **BS**(아이디어·시장/경쟁 조사) | 문제·타깃·차별화가 분명한가 |
| 2 | `/plan` | **PRD + Roadmap(RM)** | 범위·마일스톤·핵심 기능이 맞는가 |
| 3 | `/requirement`(권장) | **URS·UCS·SRS** | 화면이 감쌀 요구가 정의됐는가 |

- 대시보드에서 각 문서를 열어 **검토·수정**한다(채팅 빌더로 피드백 반영 가능).
- **요구(UCS/SRS)를 만들어두면** 이후 화면이 `covers`로 요구와 연결돼 추적 매트릭스가 완성된다(권장). 없어도 와이어프레임 자체는 가능.

> 이 단계의 결과(검토된 계획)가 다음 단계에서 **어떤 화면이 필요한지**의 근거가 된다.

---

## 2단계 — 와이어프레임 생성 지시

**와이어프레임 탭의 Claude 채팅(빌더)** 에서 자연어로 지시한다. 예: *"검토된 계획대로 와이어프레임 만들어줘"*, *"모임 목록·정산 상세·지출 추가 화면 만들어줘"*.

Claude가 수행하는 것(자동):

1. **화면 도출(개수 제한 없음)** — 계획(BS·Roadmap·PRD·UCS/SRS)을 읽어 이 제품에 필요한 화면을 **전부** 정한다. 각 화면에 `SCREEN_CODE`(대문자 토큰, 예 `LIST`·`DTL`) 부여. 계획이 비어 화면을 못 정하면 **어떤 화면이 필요한지 먼저 물어본다.**
2. **SAE 스펙 저작(화면마다 1개)** — `.ouroboros/docs/wireframes/WF-<CODE>.json`을 만든다. **모든 UI 요소에 요소코드(`<SCREEN>.<NN>`) + 상태(State)·액션(Action)·이펙트(Effect)** 를 명세(방법론=`_WIREFRAME-SAE-METHODOLOGY.md`). 이게 화면의 "설계도"다.
3. **생성(헤드리스)** — `wfgen.py`가 저작된 스펙 **전량**을 penpot Wireframes에 실제 화면 목업으로 그린다(요소를 유형별 시각표현·공간배치, 컴포넌트로 승격해 Assets 등록, 화면코드 라벨은 접이식 그룹).
4. **아티팩트 발급·추적** — `wfscan.py`가 각 프레임을 PLM `Wireframe` 아티팩트(WF-<CODE>)로 발급하고, `covers`로 UCS/SRS와 연결한다.
5. **렌더 검증** — 각 화면을 이미지로 렌더해 의도대로·도메인에 맞게 그려졌는지 확인한 뒤 보고한다.

결과는 **와이어프레임 탭의 penpot 미리보기**에 바로 뜬다(새로고침).

> **화면 수 제한 없음**: 예전엔 스펙이 없으면 예시 3화면(LIB/RDR/PIPE)으로 폴백했으나 제거됨. 이제 화면은 오직 이 프로젝트의 SAE 스펙에서 나오며, 필요한 만큼 만든다.

---

## 3단계 — 피드백·수정·보완 루프

penpot 미리보기(또는 렌더 이미지)를 보며 채팅으로 계속 고친다.

| 요청 예 | Claude 동작 |
|---------|-------------|
| "이 화면 검색바를 상단으로 올려줘" | 해당 `WF-<CODE>.json` 스펙 수정 → 그 화면만 재생성 → 재렌더 |
| "정산 상세에 '완료' 배지 추가" | 스펙에 요소 추가 → 재생성 |
| "설정 화면도 추가해줘" | 새 `WF-<CODE>.json` 저작 → 생성(전량 반영) |
| "카드가 너무 빽빽해" | archetype/레이아웃 조정 → 재생성 |

- 변경은 **penpot에 직접 반영**된다(문서 빌더와 달리 별도 [반영] 버튼 없음). 미리보기를 새로고침해 확인.
- 세밀한 단건 수정은 update-file RPC로 개별 요소만 바꾸기도 한다.
- 만족스러우면 그대로 두면 된다 — Wireframe 아티팩트·covers·추적 매트릭스가 이미 서 있다.

---

## 추적성 — 화면이 요구와 어떻게 연결되나

```
URS (이해관계자 니즈)
  ↑ derives_from / elaborates
UCS · SRS (유스케이스 · 기능요구)
  ↑ covers
Wireframe (화면 — WF-<CODE>)
```

- 대시보드 **매트릭스/그래프**에서 `URS → SRS → Wireframe` 사슬을 본다.
- 화면(WF-<CODE>)을 열면 `covers` 대상(UCS/SRS) + SAE 본문 + penpot 딥링크(loc)를 확인.
- 요구에서 역추적하면 그 요구를 **어느 화면이 구현하는지** 보인다.

---

## 자주 묻는 것

- **화면이 3개만 나와요** → (해결됨) 계획에서 화면을 도출해 화면마다 SAE 스펙을 저작하면 그 수만큼 나온다. 스펙이 없으면 생성기가 "스펙을 먼저 저작하라"고 안내하고 멈춘다(예시 3화면 폴백 제거).
- **엉뚱한(다른 제품) 내용이 나와요** → 생성기는 SAE 스펙의 요소 라벨만 쓴다(도메인 중립). 스펙 라벨을 이 제품에 맞게 쓰면 그대로 반영된다.
- **요구 없이 화면만 빨리 보고 싶어요** → 가능. 단 `covers` 추적은 나중에. 나중에 요구를 만들고 링크하면 매트릭스가 채워진다.
- **penpot 로그인이 안 돼요** → 계정에 이메일이 있어야 한다(관리자에게 계정 이메일 등록 요청). 와이어프레임 탭이 안내를 띄운다.

## 도구 레퍼런스

| 도구 | 역할 |
|------|------|
| `plugin/plm-hub/scripts/wfgen.py` | SAE 스펙 → penpot 화면 보드 생성(헤드리스·전량·컴포넌트·archetype 자동) |
| `plugin/plm-hub/scripts/wfscan.py` | penpot 프레임 → PLM `Wireframe` 아티팩트 멱등 발급 |
| `.ouroboros/docs/_WIREFRAME-SAE-METHODOLOGY.md` | SAE 표기법(요소코드·상태·액션·이펙트·archetype) |
| 와이어프레임 탭 채팅(빌더) | 위 전 과정을 대화로 구동(SRS-042) |

archetype: `list_grid`(카드 그리드) · `workspace`(분할 작업공간) · `console`(단계 플로우) · `form`(입력 폼) · `auto`(범용). 스펙의 `archetype` 필드로 지정하거나 자동 선택.
