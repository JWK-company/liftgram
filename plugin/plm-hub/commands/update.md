description: 우리가 관리하는 모든 워크플로우 플러그인(plan·code·plm-hub·plm-channel)을 서버에 배포된 최신 버전으로 일괄 업데이트.
---

`plan`·`code`·`plm-hub`·`plm-channel` 플러그인을 **서버(`/template/download`)에 배포된 최신 버전**으로 한 번에 업데이트한다.

> 왜 이 명령이 필요한가: `jwk-platform` 마켓플레이스는 **로컬 저장소**를 소스로 등록한다. 그래서 `claude plugin update` 단독으론 옛 로컬 파일만 재읽어 실제 새 버전이 있어도 "이미 최신"으로 정체된다. 이 명령은 서버 배포 스냅샷을 받아 로컬 소스를 먼저 최신화한 뒤 갱신한다(git 유무 무관·universal).

## 수행

1. `${CLAUDE_PLUGIN_ROOT}/scripts/plm_update.sh` 를 실행한다. 스크립트가:
   - `/template/download`(서버 배포 번들·무인증)를 받아 로컬 마켓플레이스 소스의 `plugin/`·`.claude-plugin/marketplace.json` 를 최신화한다. **방식이 설치 형태에 따라 다르다** — `plugin/` 이 살아 있는 git 저장소(개발 체크아웃·서브모듈)면 **파일 병합**(잔재 정리는 git 담당), 그렇지 않은 일반 설치본이면 `plugin/` 을 통째로 **전면 교체**한다(`plugin.new` 로 복사 → 구 디렉토리 `rm -rf` → 스왑. 리네임된 옛 파일이 남아 커맨드가 중복 등록되는 것을 막기 위함).
     - 사용자 기획 산출물(`.ouroboros/docs/`)과 `.env` **값**은 건드리지 않는다. 다만 아래 1-b 의 설정 파일들은 예외다.
   - `claude plugin marketplace update` + 각 플러그인 `claude plugin update`(프로젝트 스코프 우선, user 폴백).
1-b. **이 스크립트는 아래 설정 파일도 자동 교정(self-heal)한다** — "플러그인만 갱신"이 아니다. 이들은 커밋 대상인 경우가 많아 실행 후 예기치 않은 diff 가 생길 수 있으니, 실행 전 `git status` 로 확인하라.

   | 대상 | 무엇을 하나 | 백업 |
   |---|---|---|
   | `.ouroboros/env/mcp-auth.sh` | 번들 최신본으로 **덮어씀**(ouro 토큰 자동 발급 지원) | 없음 |
   | 프로젝트 `.mcp.json` | `ouroboros` 블록에 `headersHelper` 주입 + 구 `headers` 제거 | 없음 |
   | 프로젝트 `.claude/settings.json` | `.ouroboros/hooks/*` 를 가리키는 **레거시 훅 항목 제거**(커스텀 훅은 보존) | 없음 |
   | `~/.claude/plugins/known_marketplaces.json` | 마켓플레이스 등록 경로를 현재 디렉토리로 교정 | `.bak-<타임스탬프>` |
   | `~/.claude/plugins/installed_plugins.json` | 사라진 디렉토리의 유령 설치 항목 purge(우리 4종 한정) | `.bak-<타임스탬프>` |

2. 스크립트 출력(플러그인별 갱신/최신 여부 + 위 self-heal 로그 `[+] …`)을 사용자에게 그대로 보고한다.
3. **반영 안내**: 새 스킬·훅은 **Claude Code 세션 재시작** 후 로드됨을 명시한다.

## 범위·주의

- 이 명령은 **로컬 플러그인만** 업데이트한다. `mcp-server`·대시보드 등 **서버 컴포넌트는 범위 밖**(관리자가 docker로 배포).
- "서버 배포 최신" = `/template/download` 번들 = 마지막 mcp 빌드 시점의 플러그인. 관리자가 플러그인을 바꿨다면 template 재생성 + mcp 재배포가 선행돼야 이 명령에 반영된다.
- 개발용 git 체크아웃에서 로컬 plugin 수정 중이라면, 병합 덮어쓰기가 작업트리를 더럽힐 수 있다(플러그인 개발자는 `git pull` 사용 권장).
- **git 저장소가 아닌 설치본에서는 `plugin/` 이 전면 교체된다** — 그 디렉토리 안에 손으로 넣어 둔 파일이 있으면 사라진다. 커스터마이즈는 `plugin/` 밖에 두어라.

## 와이어프레임 작업용 사본 — **서버 버전 게이트**(감사 X1 · Y1~Y3 · 치명)

와이어프레임 댓글 반영은 **작업용 사본에서만** 하도록 서버·대시보드가 강제한다. 그런데 실제로 penpot을 만지는 것은 이 기계의 플러그인이고, 마켓플레이스 전달이 수동이라 **서버만 새것이고 플러그인이 뒤처지는 스큐가 실제로 일어났다**(라이브에서 `plm-hub 0.6.20` / `plm-channel 0.1.24`). 그 조합은 배포 전보다 나쁘다 — 대시보드가 사본을 만들어 penpot 파일이 2페이지가 되는데, 옛 도구엔 페이지 스코핑(`--page`)·역할 가드가 없어 **정본을 오염시킨다.**

그래서 서버가 **버전 게이트**를 건다:

- 릴레이(`plm-channel 0.1.31+`)가 SSE 구독 때 `versions=plm-channel=…,plm-hub=…`를 실어 보낸다(헤더 `x-plm-plugin-versions`도 함께).
  - **0.1.31이 최소인 이유**(감사 Y1): 0.1.30은 형제 상대경로(`../../plm-hub/…`)로만 plm-hub를 찾았는데, 실제 설치본은 `~/.claude/plugins/cache/<마켓>/<플러그인>/<버전>/` 구조라 그 경로가 **존재하지 않는다** → plm-hub가 영원히 미보고였다. 0.1.31은 설치 대장(`installed_plugins.json`)을 읽어 **이 프로젝트에 설치된 plm-hub**를 찾는다(저장소 체크아웃도 그대로 동작). 못 찾으면 구독 로그에 "어디를 봤는지 + 해결법"을 남긴다.
  - 탈출구: `PLM_HUB_PLUGIN_DIR=<plm-hub 디렉터리>` 또는 `PLM_HUB_VERSION=<버전>`으로 직접 지정할 수 있다.
- 서버는 그 값을 `session_channels.capabilities.versions`에 남기고 **두 지점**에서 검사한다(감사 Y2·Y3):
  1. **사본 만들기** — 그 프로젝트에 붙어 있는 세션 중 하나라도 기준 미만이면 거절.
  2. **세션 작업 배정** — 와이어프레임 피드백 반영 work가 세션에 도달하는 모든 경로:
     - `POST /sync/enqueue`(대시보드 전송) = **거절 + 사유**(담당자의 세션이 미달일 때),
     - `POST /sync/claim`·재접속 리플레이 = 그 **세션 단건**을 판정해 **미배정**(거절이 아니라 보류 — work는 큐에 남고 최신 세션이 붙으면 흘러간다).
  오염은 "사본을 만들 때"가 아니라 **옛 도구가 사본 있는 파일에서 작업할 때** 일어나므로, 사본 재사용(대시보드가 POST를 안 부르는 경로)도 이 배정 게이트가 덮는다.
- **버전을 보고하지 않는 세션은 거절**(fail-closed)이지만, **세션이 하나도 없으면 막지 않는다**(감사 Y3 — 오염 주체가 없는 상태다).
- **승격·되돌리기·마감·버리기(`promote`/`undo`/`close`/`discard`)는 게이트하지 않는다** — 관리자가 대시보드에서 하는 행위이고 터미널 세션 유무와 무관해야 한다. 이미 만든 사본을 확정·처분하는 길은 언제나 열려 있어야 한다.

| 환경변수(서버) | 기본 | 뜻 |
|---|---|---|
| `WF_COPY_ENABLED` | `1`(켜짐) | `0`이면 생성·승격·되돌리기 동결(조회·버리기·마감은 열림 — 이미 만든 사본의 출구는 항상 있다) |
| `WF_COPY_PROJECTS` | **(미설정·빈값 = 폐쇄)** | **프로젝트 단위 개방** — 쉼표 목록(`p1,p2`). **전체 개방은 `*`를 명시**해야 한다. 전역 스위치와 AND. **새 사본 생성만** 제한하고 이미 만든 사본의 승격·정리는 막지 않는다 |
| `WF_COPY_VERSION_GATE` | `enforce` | `warn`=로그만 · `off`=해제 |
| `WF_COPY_MIN_PLM_HUB` | `0.6.25` | plm-hub 최소 버전 |
| `WF_COPY_MIN_PLM_CHANNEL` | `0.1.31` | plm-channel 최소 버전 |
| `WF_COPY_VERSION_TTL_SECS` | `900` | 게이트가 세션을 조회하는 창(초). ⚠ **실효는 이 값이 아니다** — 아래 `CHANNEL_PRESENCE_TTL_SECS`(120초)가 먼저 세션을 `offline`로 내리므로 **둘 중 작은 쪽**이 실제 판정창이다. 이 값만 넓혀도 변화가 없다 |

> ⚠ **`WF_COPY_PROJECTS`의 빈값은 "전체"가 아니라 "폐쇄"다**(감사 Z5 · 2026-07-31에 뒤집힘).
> 예전 문서는 "(빈값=전체)"라고 적혀 있었고 그것이 이 표의 유일한 오기였다 — 그 말을 믿고 목록을
> 비워 두면 **아무 프로젝트도 안 열린다**. 값이 사라지는 방향이 개방이면, 목록을 명령형으로 넣었다가
> 재배포 1회로 유실되는 순간 **그 인스턴스의 모든 프로젝트가 열린다**. 그래서 유실 방향을 폐쇄로 뒤집었다.
> · 배포 인스턴스(=`WF_COPY_ENABLED`가 설정된 환경)에서 미설정·빈값 → **폐쇄**.
> · 두 값 모두 미설정(로컬 개발·CI) → 기존대로 허용. 그래서 **로컬에서 시험하면 "빈값=전체"처럼 보인다** — 오학습 주의.
> · 개방은 반드시 **매니페스트 선언 + 재배포**로 한다(`kubectl set env` 금지 — 다음 apply에 덮인다).

**세션 presence 레버**(위 판정창의 실제 주인 · `plm-channel` 릴레이 SSE 기준):

| 환경변수(서버) | 기본 | 뜻 |
|---|---|---|
| `CHANNEL_PRESENCE_TTL_SECS` | `120` | 이 시간 넘게 접속 신호가 없는 세션을 `offline`로 내린다 = **게이트의 실효 판정창** |
| `CHANNEL_PRESENCE_SWEEP_SECS` | `60` | 정리 주기(최소 10) |
| `CHANNEL_PRESENCE_SWEEP_ENABLED` | `1` | `0`이면 정리 중단 — 좀비 세션이 쌓여 `enforce`가 **영구 전면 차단**이 될 수 있다(감사 Z2). 끄지 말 것 |
| `CHANNEL_PRESENCE_RETENTION_DAYS` | `30` | ⚠ **파괴적** — 이 기간이 지난 세션 행을 **삭제**한다(0=삭제 안 함). "그 기계가 그때 무슨 버전이었나"의 감사 이력이 조용히 사라지는 유일한 레버다(감사 AA6) |
| `CHANNEL_ACTIVITY_TTL_SECS` | `60` | 활동 신호(busy/idle)가 "살아 있는 세션"으로 인정되는 마지막 접속 경과 |

**현황 조회**(감사 Y6): `GET /wireframe/version-gate?project=<프로젝트>` — 모드·기준 버전·**세션별 보고 버전과 충족 여부**·차단 여부·보류 work 수. 와이어프레임 탭 상단 배너가 같은 값을 읽는다. **`enforce`로 올리기 전에 이 조회로 코호트를 확인하는 것이 정해진 절차다**(예전엔 확인 수단이 없어 켜는 순간 사용자 거절로 실태를 알았다).

**어느 필드를 보고 판정하나**(감사 R6 §7 — 지표 교정):

| 알고 싶은 것 | 필드 | 주의 |
|---|---|---|
| 파일럿을 열어도 되나 / `enforce`로 올려도 되나 | **`cohort_ready`**(= `live_sessions ≥ 1` AND 전원 `ok`) | `stale_sessions == 0`으로 판정하지 말 것 — "전원 최신"과 "**아무도 안 붙어 있다**"가 같은 `0`이다. 판정창이 실질 120초라 **평시 0이 기본값**이다 |
| 왜 아무 일도 안 일어나나 | `pending_wf_work` | 아직 **아무 세션에도 못 간** work만 센다(진행 중은 제외 — 옛 판정은 진행분까지 세어 거짓 경보를 냈다) |
| 같은 피드백이 두 번 반영되나 | `stalled_wf_work` | 전달됐는데 완료 보고 없이 재배달 창(60분)을 넘긴 work(감사 AA7). 0이 아니면 `[전달 취소]` 후 재전송 |
| 지금 막히나 | `ok` · `blocked` | **게이트 판정의 거울**이다. 세션 0도 `ok:true`(Y3) — 코호트 상태가 아니다 |

**거절을 만났을 때 사용자가 할 일**: `/plm-hub:update` → **Claude Code 세션 재시작**(릴레이가 새 버전으로 다시 구독해야 서버가 그 값을 본다) → 다시 시도. 세션을 그냥 **종료**해도 된다(세션 0은 막지 않는다).

> ⚠ **이 게이트는 안전장치이지 보안통제가 아니다**(감사 Y7). 버전은 릴레이가 스스로 보고하는 값이라, 프로젝트 멤버가 마음먹으면 구독 URL의 `versions=`를 조작해 통과할 수 있다. 실수로 옛 도구가 정본을 망가뜨리는 것을 막는 장치이며, 악의적 우회를 막지는 못한다.
