# SRS-083 — 세션 갱신 경합에도 로그인이 유지된다 — refresh 회전 유예 창·토큰 계열 재사용 탐지·탭 간 갱신 직렬화

> 타입 SRS · 그룹 liftgram · ADStudio가 `SRS-083.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

### 요구 서술

로그인한 사용자는 앱을 연 직후 당겨서 새로고침하거나, 「새 버전」 띠로 새로고침하거나, PWA와 브라우저 탭을 함께 열어 두어도 로그아웃되어서는 안 된다. 지금은 refresh 토큰을 회전할 때 옛 토큰을 즉시 폐기하므로, 갱신 응답(새 쿠키)이 브라우저에 닿기 전에 문서가 사라지거나 두 문서가 같은 쿠키로 동시에 갱신하면 다음 갱신이 401을 받아 세션 전체가 끊긴다(화면 정리 P4 /qa code H-1).

시스템은 회전으로 폐기된 refresh 토큰을 짧은 유예 창(30초) 안에서는 같은 토큰 계열(family)의 새 토큰으로 다시 바꿔 주고, 유예 밖에서 재사용되면 탈취로 보고 그 계열 전체를 폐기한다. 로그아웃·전체 폐기로 끊긴 계열에는 유예를 주지 않는다. 화면은 탭 사이에서 갱신을 하나씩 돌리고, 갱신 401 한 번으로 곧장 로그아웃하지 않고 짧게 기다려 한 번 더 시도한다.

### 수용 기준

- 같은 refresh 쿠키로 갱신 두 번을 동시에 보내면 둘 다 200이고, 이후 갱신도 통한다.
- 갱신 응답을 받지 못하고(요청이 끊긴 뒤) 같은 쿠키로 다시 갱신하면 통한다 — 그 사이 새 토큰(후계)이 한 번도 쓰이지 않았으면 그 후계를 대체해 새 토큰을 준다(「미사용 후계」 규칙 · /qa code H-1). 한 계열에 살아 있는 토큰은 언제나 하나다.
- 후계가 이미 쓰인 옛 토큰, 또는 대체된 토큰을 30초 밖에서 다시 쓰면 401이고, 그 계열의 살아 있던 토큰도 함께 폐기된다(재사용 탐지 · RFC 9700 §4.14.2). 공격자가 먼저 쓰든 나중에 쓰든 결국 한쪽이 무효 토큰을 내밀어 드러난다.
- 로그아웃한 기기의 토큰은 유예 안에서도 401이며, 다른 기기 세션은 영향받지 않는다.
- 탭 두 개가 동시에 열려 갱신해도 둘 다 로그인 상태를 유지한다(e2e).
