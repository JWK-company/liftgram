# RM-015 — P1 코어 강화 — 종목 변형 기록 모델 + 로깅 정밀도 (BS-002 반영)

> 타입 Roadmap · 그룹 liftgram · ADStudio가 `RM-015.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **covers** → SRS-028, SRS-029, SRS-033, URS-016

### 목표 / 범위

이 로드맵은 같은 종목을 서로 다른 실행 조건에서 수행할 때 생기는 기록 왜곡을 제거하는 **P1 코어 정확성 강화**를 목표로 했고, M0~M2가 전량 구현·출시되었다. 종목은 불변으로 두고 실행 조건을 변형 축(variant axis)으로 분리 기록한다는 골격은 그대로 산출되었으나, 실사용 검증을 거치며 두 곳이 초안과 갈렸고 **ADR-026(ADR-025 대체)**이 이를 사후 확정했다 — ① 변형 버킷 축은 **기구(equip) 1차원**으로 좁혀졌고 그립·팔은 종목이 아니라 **세트 속성**(`set_logs.arm` v8 · `set_logs.grip` v11)으로 소유가 옮겨졌다. ② 세트 정밀도는 치팅 비중·부호 보정무게가 아니라 부분반복 분리 입력(`partial_reps` v9)과 종목 단위 하중모드·사용자 체중에서 파생하는 유효무게(`load_mode` + `user_profiles.bodyweight_kg` v12)로 구현되었다. 결과적으로 이전기록·PR·볼륨·히스토리는 `(exercise_id, variant_key)` 버킷 — 실질적으로 기구 축 — 으로 갈라지고, 세트별 그립·팔은 버킷을 나누지 않는 기록·표시 속성으로 남아 사용자가 비교 가능한 진짜 진척을 본다.

범위는 **BS-002 인앱 피드백(유효 21건) 트리아지 결과**를 그대로 반영한다. 이미 db34d85로 구현된 브랜드별 기록 분리(#21)를 변형 모델의 구현 선례이자 일반화 근거로 삼아 SRS-028(변형 모델)·SRS-029(로깅 정밀도)를 신규 발급하고, 회귀성 열린 버그(#22 진행 중 종목 교체, #15 루틴 종목 검색)를 클러스터 작업보다 먼저 처리한 뒤, 나머지 대기 항목을 기존 승인 SRS(SRS-001/002/004/005/007/009/018)로 매핑해 P2~P3 백로그로 배치한다.

단계 = **Phase 1 — Wedge (Core Accuracy)**, 목표일 = 2026-12-31, 상태 = Active. 이 축은 순수 기록앱과의 차별화 쐐기이며 이후 소셜·마켓플레이스 레이어(Phase 2+)의 데이터 신뢰 기반이 된다.

> **포함(In-scope): **스키마 v6(변형 canonical key + 개별 차원 컬럼)과 후속 v8~v12(세트별 `arm`·`grip`, `partial_reps`, `load_mode` + `bodyweight_kg`), 무손실 마이그레이션(v5 `machine_variant` 계승 + v11 그립·팔 버킷 병합 백필), prev/PR/volume/history 버킷 필터의 `variant_key` 전환, 열린 버그 #22·#15.
> 
> **제외(Out-of-scope): **그립·팔별 이전기록·PR 분리(세트 속성으로 이관되어 버킷을 나누지 않는다 — ADR-026 트레이드오프. 필요 시 세트 단위 group-by 분석으로 접근), 그립 방향/폭 축 분리(축 자체가 버킷에서 빠져 canonical 문자열 규약만 호환용 보존), 소셜·이미지·팔로우 추천(#25)은 P3 백로그로 이월.

### 마일스톤

1. **M0 (P0) 열린 버그 우선 처리 — 회귀 결함 즉시 수정.**

  - **#22 진행 중 종목 교체 불가** — 삭제 후 재삽입해야 하는 현행을 인라인 교체로. SRS-004(진행 흐름) 결함이므로 신규 요구 발급 없이 버그로 처리.
  - **#15 루틴 생성 시 종목 검색 불가** — 검색어로 리스트가 뜨지 않는 SRS-002(루틴 편집) 결함. 클러스터 작업보다 먼저 착수.
2. **M1 (P1) 변형 모델 + 스키마 v6 + 무손실 마이그레이션 — SRS-028 / SAD-019 / ADR-026(ADR-025 대체).**

  종목 불변·실행조건 변형 축 데이터 모델을 발급했다. 발급 시점 초안은 (equip·grip·arm) 3차원이었으나, 한 종목 안에서 세트마다 원암/투암·그립을 섞는 실제 수행 방식과 버킷 희소화 때문에 **버킷 축은 기구(equip) 1차원으로 확정**되고 그립·팔은 세트 속성으로 이관되었다. BS-002 근거: #26 원암/투암, #19 그립(언더/뉴트럴), 선례 #21 브랜드 전환(db34d85 완료). 이관 근거: 후속 인앱 피드백 #30·#33·#36.

  - SCHEMA_VERSION 6 — `workout_exercises`·`routine_exercises`에 `variant_key`(indexed, 파생) + `variant_equipment / variant_grip / variant_arm` 개별 차원 컬럼 추가. 실제 운용에서 채워지는 것은 `variant_equipment` 뿐이며 `variant_grip`·`variant_arm`은 v11 이후 dead column(읽기 하위호환).
  - canonical key 규약: 고정순서 [equip, grip, arm], 세그먼트 `"<dim>:<value>"` 를 `|` 로 조인, 모든 차원 기본이면 `null` (v5 기본 버킷과 동일 표현). 규약·순서는 향후 축 재도입 시의 문자열 호환을 위해 그대로 두되, 런타임이 생성하는 세그먼트는 equip 하나뿐이다.
  - **무손실 마이그레이션: **레거시 `machine_variant='hammer'` 가 신규 `equip:hammer` 와 같은 문자열 버킷이 되도록 equip 값공간에 브랜드 키를 편입 → 기존 완료기록과 신규 선택이 동일 버킷에 병합. machine_variant 컬럼·인덱스는 유지(WatermelonDB dropColumn 부재 + fallback).
  - **세트 소유 이관(v8/v11): **`set_logs.arm`('uni'=원암, null=투암)·`set_logs.grip`(over/under/neutral/wide/close, 표시전용) 추가. 종목 변형 셀렉터(VariantSelector)는 기구(레벨1)·머신 브랜드(레벨2) 2축만 노출하고, 그립·팔은 세트 행 ▼ 펼침에서 세트별로 지정한다. 레거시 행은 `backfillDropGripArmV11`이 grip/arm 컬럼을 지우고 `variant_key`를 기구만으로 재계산(부팅 시 멱등) → 같은 종목이 출처(즉석·루틴)에 따라 여러 버킷으로 파편화되어 이전기록이 비던 문제 해소.
  - prev/PR/volume/history 버킷 필터를 `Q.where('machine_variant', v)` → `Q.where('variant_key', key)` 로 치환. 순수 도메인 계산(volume·1RM·PR 비교)은 버킷 무관이라 재사용. 세트별 grip/arm은 어떤 조회에서도 필터로 쓰이지 않는다.
3. **M2 (P1) 로깅 정밀도 — 부분반복 · 하중모드 유효무게 — SRS-029(하중모드는 SRS-033으로 분화).**

  세트 반복의 질과 유효 부하를 정밀 기록한다. BS-002 근거: #13 깔짝(치팅) 횟수, #11 마이너스/가중 무게. 초안이 전제했던 `strict_reps`·`load_adjust_kg`는 구현 단계에서 한 번도 계산에 연결되지 않은 채 아래 두 필드로 대체되었다(ADR-026).

  - `set_logs.partial_reps`(v9) — 주 입력 `reps`를 정자세 횟수로 두고 부분반복(깔짝)만 별도 입력. 볼륨·추정1RM·PR에서 제외한다(`effectiveReps`는 `reps`를 그대로 반환). 초안의 '치팅분 차감' 대신 '정자세를 주 입력으로, 깔짝을 부가 입력으로' 뒤집은 형태.
  - `load_mode` + `user_profiles.bodyweight_kg`(v12) — 보정을 세트가 아니라 종목 단위 하중모드에서 파생한다. `resolveLoadMode`(명시 load_mode 우선, 없으면 equipment==='bodyweight'면 bodyweight, 그 외 external) → `effectiveWeightKg`(assisted=max(0, 체중−무게) · bodyweight=체중+가중 · 체중 미설정이면 raw 무게 폴백). #11의 마이너스/가중 요구를 세트당 입력 0회로 충족.
  - 볼륨/PR/1RM이 **유효무게 × 정자세 reps** 하나로 통일되도록 도메인 계층 확장. `getRecentPRs`·`bestEstimatedOneRepMax`도 유효무게 기준으로 전환되어 어시스트 종목의 1RM 역설이 해소되었다. `strict_reps`·`load_adjust_kg`는 dead column으로 잔존(읽기 하위호환, 계산·UI 미사용).
  - 입력 UI는 세트 행의 ▼ 펼침 상세 패널에 둔다 — 인앱 피드백 #36("세트별 정보가 많아 휴대폰에서 꾸겨져 보임") 대응으로 메인 세트 행에서 상세로 내렸다.
4. **M3 (P2) 루틴/DB·메모 백로그 — 기존 SRS 확장.**

  - **#14 종목명 수정 + 텍스트 종목 추가** → SRS-001(종목 DB) + SRS-002(루틴 편집) 확장. 로깅 인접·저비용이라 P2 선두.
  - **#9 분할 기반 자동 루틴 생성** → SRS-009(프로그램 생성기) 확장. 분할 수 + 근육 선택 → 루틴 자동.
  - **#20 슈퍼세트(길항근)** → SRS-002(루틴 구조) + SRS-004(진행 흐름) 확장. 변형이 아니라 묶음 실행 흐름이라 SRS-028 아님.
  - **#7 · #24 메모/팁** → 신규 SRS(메모/티칭) 또는 SRS-005 경량 확장으로 통합 발급. 운동별 그날 느낌 + 날짜별 팁·캘린더 조회·상급자 팁 승계.
5. **M4 (P3) 소셜 · 이미지 · UX 백로그 — 후속 확장.**

  - **#8 종목 이미지** → SRS-001(종목 DB) 확장. 종목별 썸네일(에셋 비용으로 P3). #19 그립 표시 UI도 M1 변형 모델 위에서 함께 노출.
  - **#25 팔로우 추천** → SRS-018(디스커버리) 확장. 기록·루틴 분석 기반 사용자 추천.
  - **#23 피드 루틴 가져오기** → SRS-018 + SRS-007(피드/공유) 확장, ADR-019(관문 공유) 정합. 썸네일 → 브랜드/종목 상세 + 루틴 임포트.
  - **#12 휴식 배경 신호** → 종료음·진동(de1824e)으로 부분 대체됨, 요청한 배경 깜빡임 시각 신호는 미적용 → UX 재검토 대상.

### 개정 이력

**2026-07-20 — 실제 산출 반영(계획서 → 산출 기록). **M0~M2가 전량 구현·출시된 뒤 코드 감사(path:line 전수 확인) 결과 본문 두 곳이 구현과 어긋나 있어 바로잡았다. ① M1의 변형 버킷 축 서술 — 초안은 (equip·grip·arm) 3차원으로 이전기록·PR·볼륨이 갈린다고 했으나, 실제 버킷은 기구 1차원이고 그립·팔은 `set_logs.grip`(v11)·`set_logs.arm`(v8) 세트 속성으로 이관되어 어떤 조회에도 필터로 쓰이지 않는다(`recordVariant`가 grip/arm을 항상 null로 고정, `backfillDropGripArmV11`이 레거시 버킷을 기구 축으로 병합). ② M2의 유효 부하 서술 — `strict_reps`·`load_adjust_kg`는 계산에 한 번도 연결되지 않은 dead column이며, 실제로는 `partial_reps`(v9) 제외와 `load_mode`+체중 파생 유효무게(v12)가 볼륨·PR·1RM을 결정한다. 두 변경의 결정 근거는 **ADR-026**(ADR-025 대체)에 기록되어 있으며, 본 개정은 로드맵 본문을 그 결정에 정합시킨 것이다. M0(#22·#15)·M3(#14·#9·#20·#7/#24)·M4 및 우선순위·트리아지 주석은 사실과 일치하여 그대로 두었다.
