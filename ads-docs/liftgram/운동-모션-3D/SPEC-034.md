# SPEC-034 — 전 종목 3D 운동 움직임 영상 제작과 앱 연결

> 타입 Spec · 그룹 liftgram/운동-모션-3D · ADStudio가 `SPEC-034.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **implements** → ADR-036, ADR-058, SRS-055

### 목표

카탈로그 전 종목의 운동 상세·운동 중 팁 그림을 704px 움직임 영상으로 바꾼다. 몸은 살색 피부·검은 반바지·깔끔한 짧은 머리, 흰 배경, 자극 부위는 빨강이다. 영상이 없거나 재생할 수 없으면 지금의 픽토그램을 그대로 보여 준다.

### 범위

- 제작 도구(신규): `src/scripts/motion/export-specs.ts`, `src/scripts/motion/motion3d.py`(자세 해석·장면·렌더), `src/scripts/motion/refine.py`(Wan), `src/scripts/motion/composite.py`(합성·인코딩·지표), `src/scripts/motion/README.md`.
- 앱 데이터(신규·생성): `src/core/src/data/exerciseMotion.data.ts`(종목 id → 영상 키).
- 앱 화면: 신규 `src/frontend/app/components/ExerciseMotion.tsx`, 수정 `src/frontend/app/exercise/[id]/page.tsx`, `src/frontend/app/components/session/ExerciseTipPanel.tsx`.
- 출처·고지: `src/core/src/data/exerciseVisual.ts`, 라이선스 화면과 그 테스트.
- 오프라인: `src/frontend/public/sw.js`에 영상 캐시와 상한.
- 영상 파일: 배포 경로는 Phase 3에서 `src/scripts/deploy-h2500-3.sh` 구조를 보고 확정한다(저장소 비대화를 피할 수 있으면 피한다).
- 범위 밖: 목록 썸네일 교체는 영상 품질 확인 뒤 Phase 3 안에서 포함 여부를 판단한다. 픽토그램 코드(`src/core/src/data/pictograms/`)는 고치지 않는다.

### 설계

입력은 픽토그램 자세 데이터다. 633행이 원형·기구·주동근 조합으로 묶이면 영상은 475개(원형 248개)다. 같은 조합의 종목은 같은 영상을 쓴다.

- 옆모습 자세: 절대각을 몸의 시상면(Y-Z)으로 옮기고, 실제 뼈 길이로 관절 위치를 계산해 손목·발목 IK 목표로 쓴다.
- 앞모습 자세: 각도를 관상면(X-Z)으로 옮긴다.
- 기구: 픽토그램 항목(벤치·패드·스택·레버·봉·상자·공·케이블·밴드)과 기구 종류(바벨·덤벨·케틀벨·EZ바·트랩바·스미스)를 3D 부품으로 만든다.
- 접촉 보정: 바닥에 닿아야 하는 손·발이 뜨거나 파묻히면 기준 관절을 축으로 몸을 돌려 맞춘다.
- 카메라: 후보 구도를 저해상도 마스크로 시험해 주동근이 가장 잘 보이는 구도를 고르고, 전 프레임이 들어오게 자동으로 맞춘다.
- 수작업 덮어쓰기: 자동 변환이 어색한 원형은 `src/scripts/motion/overrides.json`으로 고친다. 벤치·스쿼트 등 시험에서 직접 짠 10종목은 손으로 다듬은 값을 쓴다.
- 합성: 몸(손 제외)만 Wan 결과를 쓰고 손·기구·배경은 Blender 원본, 주동근은 음영을 살려 빨강을 입힌다.
- 앱: 종목 id → 영상 키 → `/motion/<키>.mp4`. `muted loop playsInline` 재생, 화면에 보일 때만 로드, 동작 줄이기면 픽토그램.

### 설계 보강(REV-054 반영)

- 입력 형식: 3D 동작 표 `src/scripts/motion/motions.json` = `keys[]`(골반 위치·회전, 척추, 손·발 목표 또는 2D 초안 자세) · `loop`(`pingpong`·`cycle`·`hold`) · 그립·너비·쓰는 쪽 · 세부 주동근 · 구도 제한. 2D 변환기는 초안을 만들 뿐이다.
- 등급: 원형마다 A 자동·B 값 추가·C 키 수작업·X 제외. 표본 40개(고위험 유형 포함) → 120개 → 전체 순서로 넓히고, A 등급 무수정 합격이 80% 미만이면 원인을 먼저 고친다.
- 1차 제외(픽토그램 유지): 목 운동, 비하인드 넥, 기요틴, 제퍼슨 컬, 노르딕, 드래곤 플래그, 플란체, 휴먼 플래그, 올림픽 리프트, 다단계 동작, 포괄 유산소. 제외 목록을 사용자에게 보고한다.
- 영상 공유: 키 = 원형×기구×주동근×그립×쓰는 쪽×변형. 동작이 다른 종목은 영상을 연결하지 않는다. 475는 고정값이 아니라 재계산 값이다. 검수는 종목 행 단위로 한다.
- 자동 지표: 무게 수평 편차, 기구 궤적, 관절 범위·꺾임, 몸-기구 관통, 접촉 잔차, 화면 이탈, 주동근 노출·동작 투영률, Wan 후 실루엣 IoU·떨림, 이미지 안전 검사. 일부러 넣은 불량을 잡는지 시험한다. 지표는 검수 면제가 아니라 우선순위용이다.
- 합성: 몸만 Wan을 쓰되 손·반바지·양말·신발·기구·배경은 Blender 원본. BT.709 색 태그, 왕복이 아닌 동작은 `loop`대로 인코딩. 프롬프트는 동작 표에서 생성한다.
- 재시작: 클립별 폴더·완료 표시·`trap`·시간 제한·실패 대기열·`manifest.json`(스크립트 SHA, Blender·MPFB·ComfyUI 커밋, 가중치 SHA-256, 입력 해시, 시드). 전역 삭제 금지.
- 배포: 영상은 git 밖, 서버 `~/liftgram_motion/release/`(추가 전용)와 맥 백업. 파일명 `<키>.<sha8>.mp4`, 배포 스크립트가 이미지 빌드 전에 `src/frontend/public/motion/`으로 복사하고 존재·해시를 검사, 끝에 표본 200·206·immutable 확인.
- 앱: 픽토그램을 먼저 그리고 `playing` 뒤 교체. Cache API + Blob(전용 `liftgram-motion`, 바이트 LRU, 내 루틴 고정, 운동 중·`saveData` 때 미리 받기 금지), 동시 재생 1~2개, 화면 밖 해제, 동작 줄이기 구독, 매핑 `import()`. 칸은 영상이 뜨면 흰색. 목록은 정지 썸네일.
- 출처: `motion3d` kind 신설, `ai`는 계속 차단, 매핑 키가 장부에 있어야 시험 통과. 영상 근처 고지 「3D 렌더링을 바탕으로 AI 보정을 거친 영상입니다」, `/licenses`에 Blender·MPFB·Wan 추가. 도구 폴더는 `GPL-3.0-or-later` 표기, 앱 코드에서 import 금지.
- 커밋: 도구는 Phase 2 전, 앱은 Phase 3 뒤 `feat/motion-3d`에 커밋. 합치기는 qa code 뒤 rebase → 메인 `src`가 5분 잠잠한지 확인 → 카탈로그 재내보내기·드리프트 시험 → ff-only → 새 커밋 목록 확인 → 그 시점 다음 minor로 배포.

### 수용 기준

- SRS-055: 모든 카탈로그 종목에 그림이 있다(영상 또는 픽토그램). 출처가 허용 목록 안에 있고 허용 목록 밖이면 테스트가 실패한다.
- 합격 영상은 끊김 없이 반복되고, 주동근이 보이며, 몸이 바닥·기구를 크게 뚫지 않는다.
- 동작 줄이기·영상 실패·미제작 종목은 픽토그램을 보여 준다.
- 영상 전체 용량은 약 50MB 안팎이고, 첫 화면 JS는 늘지 않는다.

### 테스트 계획

- 도구: 자동 지표 리포트 + 전 영상 시트 눈 검수.
- 앱: `src/core/src/domain/__tests__/`에 매핑 드리프트·허용 목록 테스트, 화면 단위 시험, 운영 빌드 e2e(재생, 대체, 오프라인 캐시, 동작 줄이기).

### 위험·주의

- 자동 변환이 어색한 원형이 많으면 덮어쓰기 작업이 길어진다. 안전에 문제 되는 자세는 영상을 내지 않고 픽토그램을 유지한다.
- 픽토그램은 뼈 길이 비율이 실제와 달라 접촉이 어긋날 수 있다.
- 얼굴은 영상마다 조금씩 다르다(ADR-058 결과 참조).
- MP4는 투명 배경이 없다. 다크 모드에서는 흰 카드 안에 넣어 보여 준다.
- GPU 사용은 사용자가 4장·시간 제한 없이 승인했다. 끝나면 해제를 확인한다.
- 다른 세션이 같은 브랜치에서 작업 중이므로 worktree `../liftgram-wt-motion`(브랜치 `feat/motion-3d`)에서 작업하고 ff-only로 합친다. 포트는 필요하면 3300을 쓴다.
