# EXE-012 — SPEC-021 구현

> 타입 Execution · 그룹 할일/잠금화면-C안 · ADStudio가 `EXE-012.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **executes** → SPEC-021

## 요약

잠금 운동 화면을 C안으로 바꿨다. 앱 라이트·다크 설정을 따르고, 루틴 이름과 닫기 버튼을 뺐으며, 운동 시간·휴식 링·세트 점을 넣었다. 광고는 넣지 않았다. 코드 리뷰에서 찾은 기존 버그 2건(꾹 누르는 중 단계 변경, 완료 직후 PIN 창)도 함께 고쳤다.

- 실패 1건은 보강한 시험의 식별자 오타(`row-theme`)였다. 고친 뒤 그 시험만 다시 돌렸고, 전체를 다시 돌리지는 않았다.
- 건너뛴 2건은 결함 주입 빌드에서만 도는 시험이다.

**에뮬레이터 확인(리뷰 반영 후, API 35):**

- 라이트·다크 화면이 맞게 나오고, 휴식 중과 운동 중의 ± 위치가 같다.
- ± 를 끌어서 벗어나면 값이 그대로이고, 탭하면 82.5 로 바뀌며 강조색과 「kg · 원래 80」이 나온다.
- 200ms 누름으로는 완료되지 않고, 1초 누름으로 완료되어 휴식 링이 시작된다. 대기열에 무게 82.5 가 들어간 완료 1건을 확인했다.

**확인하지 못한 것:**

- 리뷰 반영 후 API 30 재확인과 뒤로 가기 재확인(반영 전에는 통과).
- 작은 화면·슈퍼셋·200% 글꼴 재확인. 작은 화면과 슈퍼셋은 반영 전에만 확인했다.
- API 24~26 실기기·에뮬레이터 확인. 자동 크기 수정은 코드로만 확인했다.
- 꾹 누르는 중 단계 변경·완료 직후 PIN 창 수정의 직접 재현. 재현 시험이 없어 코드 수정과 일반 완료 동작만 확인했다.
- 실기기 확인.

## 코드 리뷰

REV-022: 채택 21 · 보류 1 · 기각 0. 채택 항목은 모두 반영했다. 보류는 `user_profiles` 구독이 `setTheme` 경로를 가릴 수 있다는 시험 한계다. 에뮬레이터에서 추가로 찾은 3건도 고쳤다.

## 범위 밖 변경

`LockWorkoutActivity.java` 의 기존 버그 2건(단계 변경 중 완료, 완료 직후 PIN 창)과 단계 키 누락을 함께 고쳤다. 같은 화면의 제스처 코드라 분리하지 않았다.

## 남은 일

- 사용자 기기에 보이려면 앱 1.5.0 설치 파일과 웹 0.63.0 배포가 필요하다. `CLAUDE.md` 에 자동 배포 줄이 없어 이번에는 커밋만 했다.
- 알림 카드에는 루틴 이름이 그대로 남아 있다. 이번 요청은 잠금 운동 화면 대상이라 바꾸지 않았다.
- 시안과 달리 휴식 중에도 ± 카드를 유지한다. 지금 되는 기능을 없애지 않기 위해서다.
