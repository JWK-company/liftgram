# SPEC-040 — 전 종목 운동 모션 재제작 — 동작 유형별 계산식과 묶음 컨펌

> 타입 Spec · 그룹 할일/모션-전종목-재제작 · ADStudio가 `SPEC-040.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **implements** → ADR-058, ADR-061, SRS-055

### 목표

앱의 전 종목 운동 영상(현재 제작 목록 기준 영상 614개, 동작 원형 248개)을 사용자가 승인한 3대운동 시험본(서버 `~/liftgram_motion3`) 수준으로 다시 만든다. 사용자는 시험본을 「훨씬 낫다, 써도 될 정도」로 평가했고(id=994), 전 종목을 이 품질로 만들기로 정했다(id=998).

품질의 기준은 겉모습보다 관절 움직임이다. 동작마다 역학 조건을 먼저 정하고 관절을 계산하며, 유튜브의 실제 수행 영상으로 확인한다. 묶음별로 사용자 컨펌을 받은 영상만 운영에 넣는다.

### 승인된 진행 방식(id=996·998)

- 나누는 기준은 부위가 아니라 동작 유형이다.
- 공통 엔진과 자동 검사를 먼저 만들고, 유형별 대표 약 12개를 컨펌받은 뒤, 묶음별로 넓힌다.
- 컨펌된 묶음부터 운영 영상을 바꾸고, 나머지는 지금 표시를 유지한다.
- 재질은 살색 없는 회색이고, 마감은 ComfyUI의 Wan 2.2다.
- GPU 4장 사용을 허가받았다. 쓰기 직전 비어 있는지 확인하고, 묶음이 끝나면 바로 반환한다.
- 최종 목표는 전 종목이다. 아직 맞다고 확신하지 못한 종목은 컨펌 전까지 영상을 바꾸지 않는다.

### 설계

#### 계산 방식

Blender IK와 옛 공통 키프레임 방식을 쓰지 않는다. 묶음별 계산식이 시간 t를 받아 고정점(발, 손, 벤치 접촉)과 궤적(바, 손잡이)을 먼저 정하고, 뼈 길이로 나머지 관절을 푼다. 무릎과 팔꿈치는 경첩축을 직접 넘겨 꼬임을 막는다. 원본은 `~/liftgram_motion3/big3.py`이고, 사람 모델은 기존 `~/liftgram_motion/base.blend`를 읽기 전용으로 쓴다.

같은 계산식을 쓰는 변형은 변수로 표현한다. 기구, 그립 폭, 스탠스, 깊이, 템포가 변수다. 움직임이 다른 동작은 변수로 뭉개지 않고 계산식을 나눈다.

#### 고정점과 구동

묶음은 사용자가 컨펌하는 단위이고, 풀이 구조는 고정점과 구동으로 나눈다. `src/scripts/motion2/catalog.json`의 키마다 두 칸이 필수다. 벤치는 몸 고정·손 이동, 푸시업은 손 고정·몸 이동이므로 같은 묶음이어도 풀이가 다르다.

- 고정점: 발, 앞꿈치, 손, 등, 좌석, 없음
- 구동: 2관절 풀이, 단관절 호(플라이, 레터럴), 척추, 견갑 단독
- `src/scripts/motion2/rig.py`는 골반·요추·흉추를 3축으로 각각 지정하고, 어깨 위치는 순방향 계산으로 구한다. 좌우 비대칭과 회전 동작을 표현할 수 있어야 한다.
- 견갑은 거상과 전인 변수를 쇄골 회전으로 구현하고, 묶음마다 시작값과 끝값을 선언한다. 쇄골 뼈만으로 상방회전이 표현되는지는 Phase 1에서 메시로 확인한다.
- 발은 평평한 발과 앞꿈치 지지를 모두 지원한다. 계산식은 올라가기와 내려가기를 따로 선언할 수 있다.

#### 유튜브 참고 규칙

- 사용자 지시(id=985·998)에 따라 원형마다 서로 다른 채널의 실제 수행 영상 2개 이상을 일반 재생으로 본다. 옆모습과 정면을 모두 확인한다.
- 내려받기, 프레임 저장, 자막 수집, 생성 모델 입력, 궤적 추출을 하지 않는다. 화면은 그 자리에서 보는 데만 쓰고 저장소와 서버에 두지 않는다.
- 확인 기록은 저장소 밖 서버의 `~/liftgram_motion3/references.json`에 둔다. 저장소가 공개이기 때문이다. 관찰은 자유 서술 없이 예/아니오 항목(고관절이 먼저 움직임, 팔꿈치가 몸통 뒤로 넘어감 등)과 시간 위치로 적는다.
- 각도 범위는 생체역학 문헌과 코칭 교재를 근거로 잡고, 영상은 순서와 자세 확인에 쓴다. 눈대중 각도를 수치 근거로 쓰지 않는다.
- 참고 기록은 앱과 저장소에 싣지 않는다. 특정 영상의 구도와 소품을 따라 하지 않는다.
- Hevy, openGym, Gym visual 자산은 입력과 참고 자료로 쓰지 않는다.

자동 검사는 사람 눈을 대신하지 않는다. 뼈대 검사는 동작 의미(팔 위치, 한 다리 동작 등)를 잡지 못하므로, 원형마다 13프레임 이상의 연속 시트와 직교 옆·정면 뼈대 시트, 영상을 직접 본 뒤 컨펌 페이지에 올린다.

제작 순서는 본 제작과 같은 프레임 수의 전 프레임 CPU 점검 → 저해상도 시트 → 원형 대표 GPU 제작 → 합격 뒤 변형 확대다. 3대운동과 대표 영상을 기준본으로 동결하고, 묶음을 시작할 때마다 다시 만들어 비교한다. 고의 오류 표본에는 기하 오류 외에 「루마니안 무릎 40°」, 「허리 꺾임」을 넣는다.

#### 합성

Wan은 머리와 손, 신발을 뺀 몸 표면에만 적용한다. 머리와 손, 신발, 바, 기구는 Blender 렌더를 그대로 쓴다. 시험본에서 Wan이 신발에 무늬를 그렸고, 머리를 복원하면 종목마다 얼굴이 달라지거나 실존 인물과 닮을 위험이 줄기 때문이다. 합성 뒤 화면 전체를 무채색으로 바꾼다.

Wan 설정은 `src/scripts/motion2/wan_profile.json`에 동결한다(시험본 기준 시드 11, denoise 0.35). 동작 문구만 `src/scripts/motion2/catalog.json`에서 받고, 인명과 인물 묘사를 쓰지 않는다. 영상은 mp4(H.264, bt709, 소리 없음)와 192px webp 썸네일을 함께 만들고, 대표 프레임 위치를 정한다.

#### 지문과 대기열

- 키마다 3단 지문을 둔다. 렌더는 CPU로 뽑은 프레임별 관절 좌표 해시와 `src/scripts/motion2/scene.py`, 모델, 렌더 설정이고, Wan은 입력 해시와 그래프, 모델 해시, ComfyUI 커밋이다. 합성은 앞 두 해시와 코드 해시다. 공통 코드를 고쳐도 좌표가 같은 영상은 다시 만들지 않는다.
- GPU별 포트로 ComfyUI를 상주시킨다. 키마다 GPU 점유와 실제 장치(OptiX)를 확인한다. 연속 2회 실패한 GPU 워커는 멈추고 키를 반납하며, 실패한 키는 다른 GPU에서 1회 재시도한다. Wan 오류는 실패로 처리하고 시간 제한을 둔다.
- 디스크: 공유 디스크 여유가 150GB 아래면 새 키를 멈춘다. 평탄화와 합성 프레임은 묶음 뒤 지우고, Blender 렌더와 Wan 출력은 배포까지, 마스크는 전 종목이 끝날 때까지 둔다. 클립당 약 52MB, 614개 1회 약 32GB다.

#### 컨펌 페이지

묶음마다 비공개 페이지 하나를 만든다. 자동 검사 예외를 맨 위에 두고, 원형별 대표 영상은 ½·¼ 속도로 볼 수 있게 하며, 기구만 다른 변형은 7장면 사진으로 보여 준다. 사용자가 틀렸다고 한 항목은 고쳐서 같은 페이지 다음 판으로 올린다.

#### 운영 반영

`src/scripts/motion2/publish.py`는 현재 `src/core/src/data/exerciseMotion.data.ts`를 기준으로 종목 id 단위로 합친다. 컨펌 기록 `src/scripts/motion2/confirmed.json`은 `{키: {sha8, 판, 답 메시지 id}}` 형식이고, 영상 해시가 다르면 내보내기를 멈춘다. 그래서 컨펌 뒤 다시 만든 영상은 통과하지 못한다. webp가 없어도 멈춘다.

내보내는 곳은 배포 스크립트가 읽는 `~/liftgram_motion/release`(추가 전용)이고, 파일 이름은 `<키>.<mp4 sha8>`이다. 서버 복사를 마친 뒤 배포한다. 키와 종목 id 연결표는 서버의 `~/liftgram_motion/jobs2.json`(633개)을 `src/scripts/motion2/catalog.json`으로 옮기고, 카탈로그 id와 집합이 같은지 시험한다. 컨펌된 키는 같은 커밋에서 `src/scripts/motion/motion_hold.json`에서 뺀다. 옛 영상 파일은 전 묶음이 끝날 때까지 지우지 않는다.

- 묶음 배포 전: `src/frontend/e2e/motion-video.spec.ts`를 묶음 대표마다 `MOTION_ID`로 반복한다. 재생 파일이 `src/core/src/data/exerciseMotion.data.ts` 값과 같은지, `motion-notice`가 보이는지 확인한다. 로컬 운영 빌드(웹 3200·API 3201, 비어 있지 않으면 다른 포트)에 영상 파일을 복사해 돌린다.
- 배포 뒤: 운영에서 묶음의 대표 영상 주소를 골라 200을 확인하고, 앱 표의 파일이 모두 존재하는지 확인한다.

### 위험·주의

- 양이 크다. 계산식과 눈 검수가 병목이다. GPU 시간은 단계별 실측 합산으로 GPU 1장 기준 약 23시간에서 3개 시험 전체 시간 환산 약 70시간 사이다. Phase 2 뒤 실측으로 다시 계산해 보고한다.
- 공유 GPU다. 사용 허가는 받았지만 다른 사람이 쓰는 중이면 그 장은 건너뛴다. 프로세스는 직접 띄운 PID로만 끈다.
- 뒤로 갈수록 어렵다. 머신과 역도 묶음은 계산식이 복잡해 첫 판 합격률이 낮을 수 있다. 품질을 낮춰 통과시키지 않고 사용자에게 보고한다.
- 유튜브 확인은 Claude in Chrome으로 사용자 브라우저에서 일반 재생한다. 자동화된 시청이 YouTube 약관에 저촉될 수 있다(약관 원문 미확인). 사용자가 달리 정하기 전까지 재생 횟수를 줄이고 수집 없이 진행하며, 이 위험을 사용자에게 보고한다. 브라우저가 끊기면 참고 없이 제작하지 않고 보고한다.
- 저장소는 공개다. 참고 기록과 내부 경로가 커밋에 섞이지 않게 한다.
- 옆 세션의 미커밋 파일(`src/scripts/motion/motion3d.py`, `reports/`, `research_notes/`)을 커밋에 섞지 않는다. 앱 표 `src/core/src/data/exerciseMotion.data.ts`는 이 세션만 고친다.
- 기존 옛 영상 중 뼈대 검수로 내려 간 125개는 그 묶음이 컨펌되기 전까지 계속 픽토그램으로 나온다.
- 디스크 여유가 약 386GB다(서버 `/home` 95% 사용, 공유). 여유 기준과 보존 규칙은 설계의 지문과 대기열 절을 따른다.
