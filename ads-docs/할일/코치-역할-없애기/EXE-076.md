### 요약

「트레이너」 역할을 없앴다. 누구나 초대 코드를 만들고 「코치로 요청」·「내 회원으로 초대」를 보낼 수 있다(서버의 의향 검사 → 계정 존재 확인). `users.trainer_intent` 는 이름 그대로 「코치 찾기에 나를 보여 주기」(기본 꺼짐)로 뜻만 바뀌었고, 코치 찾기 검색·소개·태그 노출에만 쓰인다. 「코치」 배지는 서버 파생값 `is_coach`(활성 연결에서 코치인 회원이 한 명 이상)이고 코칭 Peer·피드 프로필/사람 목록·내 계정(auth User)에 실린다. 첫 실행 안내의 트레이너 질문을 없앴고, 홈 「담당 회원」 카드는 `isCoach` 로 판단한다(코치가 아니면 연결 목록·점검을 묻지 않음 · 계정만 30초에 한 번 다시 받음). 남는 규칙(자기 자신·차단·회원 한 명당 코치 한 명·중복 요청)은 그대로이고, 코칭 요청에 분당 상한을 더했다. 작업은 worktree 에서만 했다(커밋·배포·버전 올림 없음).

### 수용 기준

1. 노출을 끈 A 가 초대 코드 → B 가 다른 기기에서 연결 → 그때부터 사람 찾기·프로필·연결 줄에 배지, 해지하면 없음 — `src/frontend/e2e/coach-role.spec.ts` 통과.
2. 코치 찾기 검색 = 노출 켠 사람만 — 같은 e2e + PG 시험.
3. 첫 실행 안내에 트레이너 질문 없음 · 요청 본문에 trainerIntent 없음 · 켜 둔 노출 유지 — coach-role 둘째 시험·onboarding.spec 통과.
4. 사람 프로필 두 버튼(360px 한 줄·잘림 없음·44px) · 내게 코치가 있으면 요청 대신 안내·초대는 남음 — coaching-v2 통과.
5. 서버: 노출 끈 사람에게 요청·초대·수락·코드 연결 됨 · 코치 한 명·차단·자기 자신 거절 유지 — Go 단위·PG 통과.
6. 코칭 안 하는 사용자 홈 → ListGrants·ListMemberDigest 0 · 30초 안 다시 보이기 Me 0 · 30초 뒤 1 — coach-role 통과.
