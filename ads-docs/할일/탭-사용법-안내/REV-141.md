## 패널 구성

Feature 등급이라 세 역할로 봤다. 병렬 작업 세션(포크)이라 하위 에이전트를 띄울 수 없었다. 그래서 한 세션이 역할을 바꿔 가며 바뀐 코드(커밋 efb2feb)를 다시 읽고, 운영 빌드에서 사진과 e2e로 확인했다. 독립 리뷰가 아니라는 한계를 적어 둔다. 메인 세션이 합칠 때 SPEC-057 코드 리뷰에 이 커밋을 함께 넣어 독립으로 한 번 더 보기를 권한다.

- 프론트엔드 구현 엔지니어 — 상태·효과·포털·이벤트
- 접근성 검토자 — 초점·키보드·aria
- 시험 엔지니어 — e2e 범위와 거짓 통과

## 핵심 지적

1. 짚기 단계가 `scrollIntoView` 로 밑 화면을 스크롤하는데, 닫아도 제자리로 돌아가지 않는다. 안내를 보고 나면 홈이 중간까지 내려가 있다.
2. 첫 그림에서는 포털 host 가 아직 없어 설명 띠가 그려지지 않는다. 그래서 초점 효과(deps `[i]`)가 아무것도 잡지 못한다. 초점이 ? 에 남아 Esc 가 덮개에 닿지 않았다(e2e 「닫기」 실패로 드러남).
3. SVG 마스크로 어둡게 칠한 판 — 사진에서 어둡게가 약해 보였다. 판 4장(booktarae 방식)이 브라우저마다 덜 흔들린다.
4. `useGuideUnseen` 은 첫 그림을 점 없음으로 두고 효과에서 판단한다. 서버 그림과 어긋나지 않게 하는 맞는 방식이다(문제 없음 확인). 다만 e2e 억제 표식이 있으면 점이 숨으므로, 점 시험이 거짓 통과하지 않도록 표식을 지우고 확인하는 단계가 필요하다 → 시험에 이미 있다(`src/frontend/e2e/tab-guide.spec.ts` 첫 시험).
5. 슈퍼세트 연습의 Space 키 — keyup 에서 기본 동작(click)을 막지 않으면 짧게 누름이 두 번 처리될 수 있다 → keyup 에서 preventDefault 한다(확인). onClick 처리기가 없어 이중 처리도 없다.
6. 대본 대상 testId 가 바뀌면 그 단계가 「설명만」으로 조용히 떨어진다. 지금 시험은 탭마다 첫 단계 하나만 짚기를 확인한다.
7. 연습 블록의 쓰기 0건 확인이 `/api/` 요청만 센다. LokiJS(기기 DB) 쓰기는 세지 않는다.
8. 영어 문구 없음(대본이 한국어 고정).
