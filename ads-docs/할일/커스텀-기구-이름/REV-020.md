## 픽스 코드 리뷰 — 커스텀 기구 이름이 재시작·업데이트마다 사라짐

### 배경

- 실기기에서 프로필 「커스텀 기구 이름」(예 「포커스」)이 앱을 업데이트하거나 다시 켤 때마다 비어 보였다. 다시 적어도 잠금 시험 뒤 또 사라졌다(2026-11-04 사용자 보고).

### 원인

- `src/frontend/app/components/profile/ProfileClient.tsx`의 입력칸 상태(`customLabels`)는 `useState` 초기값으로 **한 번만** 저장값을 읽었다.
- 첫 그림은 user를 읽기 전이다(`if (!user)`보다 위). 이때 `useUser`는 `[]`를 주므로(`src/core/src/state/userContext.tsx`) 칸이 빈 채로 굳었다.
- 화면 업데이트를 누르거나 앱을 다시 켜면 `/profile`로 바로 들어오므로 늘 이 경우가 된다.
- 그 빈 칸을 눌렀다 빠져나오기만 해도 `onBlur` 저장이 빈 값을 써서 **실제로 지웠다**.
- 고치기 전 코드에 새 e2e를 돌리면 재현된다: 새로고침 뒤 칸이 `""`.

### 바꾼 것

- `src/frontend/app/components/profile/ProfileClient.tsx`:

  - 시트가 닫혀 있을 때 저장값이 바뀌면 칸을 다시 채운다(늦게 오는 user 읽기·동기). 저장이 진행 중이면 덮지 않는다.
  - 저장은 저장값(또는 진행 중인 저장값)과 다를 때만 한다.
  - 이름 저장은 따로 줄을 세워 마지막 편집까지 반드시 쓴다. `patch()`는 busy일 때 조용히 버리기 때문이다.
  - 시트를 뒤로 가기·바깥 누름으로 닫아도 저장한다.
  - 옛 코드는 `[원본]` 주석으로 남겼다.
- `src/frontend/e2e/profile.spec.ts`:

  - 새로고침해도 칸에 보이는지 확인한다.
  - 빈 칸을 눌렀다 나와도 지워지지 않는지 확인한다.
  - 연달아 고치고 바로 닫아도 둘 다 남는지 확인한다.
  - 닫자마자 다시 열어도 편집이 보이는지 확인한다.
  - 실행마다 다른 값을 쓴다.

### 패널 구성

- React 상태·로컬 DB 저장 흐름 리뷰어 1명(Patch급)
