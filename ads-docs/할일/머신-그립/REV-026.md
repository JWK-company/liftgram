# REV-026 — 머신 손 그립 코드 리뷰

> 타입 Review · 그룹 할일/머신-그립 · ADStudio가 `REV-026.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

## 머신 손 그립 코드 리뷰

### 패널 구성

변형·기록 모델 검토자 1명이 변경 코드를 읽고 판단했습니다(스펙 없는 작은 수정). 검토자는 시험 `src/core/src/domain/__tests__/catalogRevamp.test.ts`를 돌렸고, 옛 표로 이관 계획을 직접 실행했습니다. 화면 시험은 구현 쪽에서 따로 돌렸습니다.

### 변경 요약

- `src/core/src/data/catalog/catalog.families.csv`에 `machine_grips` 열을 더했습니다. 머신 종목에만 쓰는 손 그립 목록입니다.
- `src/core/src/domain/variants.ts`의 `gripsForEquipment`가 머신이면 이 목록을, 그 밖의 기구면 기존 `grips`를 돌려줍니다. 같은 동작의 바벨·덤벨·케이블에는 그립이 늘지 않습니다.
- 커스텀 머신 종목은 동작을 알 수 없어 그립 5가지를 모두 고를 수 있습니다(`customExerciseGrips`, `src/core/src/data/catalogMeta.ts`).
- 이관 계획 `src/core/src/domain/catalogMigrationPlan.ts`도 같은 목록을 씁니다. 부팅·동기 직후의 정규화가 고른 그립을 지우지 않게 하기 위해서입니다.
- 서버 마이그레이션은 생기지 않았습니다. 종목 행은 그대로이고 동작 묶음 표만 바뀌었습니다.

### 핵심 지적과 분류

| 번호 | 지적 | 분류 | 이유·반영 |
| --- | --- | --- | --- |
| 1 | 옛 번들 기기가 새 그립을 지우고 서버로 다시 올립니다 | 보류 | 이미 배포된 번들은 코드로 막을 수 없습니다. 아래 배포 주의로 남깁니다 |
| 2 | 커스텀 머신에 그립 줄이 없습니다 | 채택 | 요구가 「머신 종목」 전체이므로 family 없는 커스텀 머신에 5가지를 허용했습니다 |
| 3 | 머신 랫풀다운의 오버가 기본 칸과 갈라집니다 | 채택 | `lat_pulldown`의 머신 전용 목록을 뺐습니다. 기존 와이드·클로즈·뉴트럴·언더는 그대로입니다 |
| 3-1 | 같은 갈라짐이 프레스·컬 등의 오버에도 있습니다 | 기각 | 이 머신들은 가로·세로 손잡이가 함께 있는 경우가 많아 오버를 고를 이유가 있습니다. 기본 칸의 뜻이 「지정 안 함」입니다 |
| 4 | 함축 그립 검사가 머신 목록을 모릅니다 | 채택 | `src/core/src/domain/catalogIntegrity.ts`가 `gripsForEquipment`로 비교합니다 |
| 5 | 이관 변경을 되돌려도 단위 시험이 실패하지 않습니다 | 채택 | 머신+언더 블록이 `changed:false`인지 보는 시험을 더했습니다 |
| 6 | 딥스 손잡이 폭을 고를 수 없습니다(추정) | 채택 | `dips`·`assisted_dip`에 와이드·클로즈를 더했습니다 |
| 7 | 머신 숄더 프레스에 언더가 없습니다(추정) | 기각 | 드문 동작이고, 필요해지면 표 한 칸만 고치면 됩니다 |

### 후속 조치

- **배포 주의:** 이 판을 배포한 뒤 되돌리면 그동안 고른 새 그립이 옛 표의 정규화로 지워질 수 있습니다. 새 판이 아직 안 닿은 다른 기기도 같은 위험이 있습니다. 옛 표로 이관 계획을 돌려 지워지는 것은 확인했고, 실기기 재현은 하지 않았습니다.
- 그립은 한 값만 고를 수 있어 「와이드+언더」는 기록할 수 없습니다. 기존 모델의 한계이며 이번 범위 밖입니다.
- 검증: `make verify` 통과(단위 시험 643개 통과·실패 0). `src/frontend/e2e/record-slots.spec.ts` 7개 통과(새 시험 2개 포함). 앱 안 확인은 하지 않았습니다.
