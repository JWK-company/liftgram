### 요약

운영 웹에 「이달의 리프터」 화면을 만들었다. 관리자만 들어온다. 한 화면에서 다음을 한다.

- 달을 고른다.
- 꾸준 후보(날 수 · 늦게 올라와 뺀 기록 · 자격 이유)와 인기 순위 상위 20을 본다.
- 인기상을 고르고, 운영진 픽은 검색해서 이유와 함께 고른다.
- 추첨 미리보기를 보고, 화면 안 확인 창을 거쳐 확정한다.
- 확정된 달에는 쿠폰을 등록한다(뒤 4자리만 보임).

씨앗 입력 칸은 없다. 서버가 미리 정한 씨앗만 쓴다.

### 테스트 결과

- `go test -race ./internal/award`: 통과. 새로 넣은 확인: 지난 기한 거부 · 한 글자 이유 거부 · 짧은 번호 가림.
- 운영 웹 `npx tsc --noEmit` · Biome: 깨끗하다.
- `node --import tsx --test admin/lib/*.test.ts`: 10개 통과.
- `E2E_PG=… bash src/scripts/e2e-admin.sh`(새 시험 DB): 운영 웹 e2e 전체 104개 통과. 그중 이달의 리프터 4개:

  - 모더레이터: 메뉴·화면 없음, RPC 0건. 토큰으로 운영 RPC 6개를 직접 불러도 모두 403.
  - 관리자: 꾸준 후보 「12일」 · 늦게 올라온 기록 「1건」 · 「메일 미확인」 이유 · 인기 후보 없음.
  - 미리보기: 추첨 대상 1명(자격 없는 사람 제외). 끝나지 않은 달은 확정이 잠김. 픽을 고르면 미리보기가 무효가 되고, 다시 보면 대상 0명.
  - 확인 창(Candidates·Confirm 응답만 대체): 미리보기 전과 이유가 없을 때는 잠김 · 요약 · 취소하면 호출 없음 · 「정말 확정」을 누르면 보낸 값(달·픽·이유) 확인.
  - 확정된 달(시험 DB에서 발표 상태로 둠):
  - 쿠폰을 등록하면 `…4321 · 상품 · 기한`만 보인다. 응답·입력칸·화면 어디에도 전체 번호가 없다.
  - 번호를 바꾸면 확인 창이 뜨고, 취소하면 그대로다.
  - 앱 API `GetMyAward`는 수상자에게만 번호를 주고, 다른 계정에는 404를 준다.
