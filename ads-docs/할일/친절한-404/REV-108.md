## REV-108 친절한 404 — 코드 리뷰(#T17)

### 요약

독립 리뷰어 1명이 t17 패치(루트·종목 not-found 자연어 화면, /downloads 없는 파일 자연어 HTML, 모양이 틀린 종목 id 404)를 읽었다. 높음 등급 결함은 없었다. 상태 코드·헤더·M-1 재발 방지·not-found 경계(generateMetadata 의 notFound 도 종목 폴더 not-found 가 받음)·다크 색 값은 요구대로라는 판단이다. 7건 중 5건 채택, 2건 보류, 기각 0건.

### 채택

- **#1 InvalidArgument 를 통째로 404 로 삼킴(중간)** — RPC 전에 proto 와 같은 규칙(`^[A-Za-z0-9._-]{1,128}$`)으로 id 모양을 먼저 보고 null. InvalidArgument 자체는 원래대로 던진다(계약이 어긋난 장애를 404 로 숨기지 않게).
- **#2 /downloads 안내만 Accept-Language 로 영어(낮음)** — 앱(lib/i18n.ts)이 ko 고정이라 이 화면도 ko 고정. 영어 문구는 앱이 언어 설정을 붙일 때 쓰도록 남겨 둠. e2e 는 「영어 브라우저여도 한국어」로 바꿈.
- **#4 뒤로 가기 폴백이 다른 사이트로 나갈 수 있음(낮음)** — Navigation API 가 없으면 같은 사이트 referrer 일 때만 뒤로, 아니면 운동 홈.
- **#5 낡은 주석(낮음)** — 루트 not-found 머리 주석을 `[원본]`/`[개선]` 으로 고침.
- **#7 e2e 약점(낮음, 일부)** — HEAD 의 Content-Length·빈 본문 확인, 129자 id 시험 추가, path-fixes 는 「죄송해요. 찾는 화면이 없어요」 전체로 비교.

### 보류

- **#3 /downloads 안내가 프로필 테마 선택을 모름(낮음)** — 서버 HTML 이라 기기 설정만 따른다. 한계를 server.mjs 주석에 적어 둠.
- **#6 NotFoundView 제목이 heading 요소가 아님(낮음)** — EmptyState 공통 문제라 다른 빈 화면과 함께 고칠 일. NotFoundView 다크 색 e2e 도 같이 미룸.
