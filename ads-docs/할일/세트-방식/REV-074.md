### 패널 구성

- 근력 운동 처방 전문가(트레이닝 코치) — 틀의 %·횟수·안전·문구
- 데이터·동기 설계 검토자 — JSON 필드의 저장·동기·서버 경로, 인덱스 짝, 반영 원자성
- 모바일 UX 설계자 — 목업과의 차이, 표시·흐름·실수 방지·누르는 자리
- 회귀·시험 검토자 — 피더가 닿는 곳, 깨질 기존 시험, 시험 계획 빈칸

### 핵심 지적

- 기준 무게를 「지난 최고 작업 세트 = 100%」로 두면 횟수를 반영하지 못한다. 6회 무게로 10회 3세트를 채우면 못 드는 처방이 된다.
- 탑세트 「최대」와 안내 「한두 개 남기고」가 모순이다. 5×5 안내 「무게를 올려요」는 앱이 하지 않는 일이다.
- 피더를 작업 세트로 셀지 정하지 않았다(볼륨·PR·근육 부하·세트 수).
- 운동 중 바꾼 표가 [옛 줄 + 새 줄]로 섞여 루틴에 반영된다. 세트 추가·삭제 때 처방 자리가 어긋난다.
- 반영 비교가 처방을 보지 않아 세트 방식만 바뀐 줄은 쓰이지 않는다.
- 「최대」 줄이 저장 왕복에서 블록 횟수를 물려받는다.
- 옛 앱이 새 필드를 지우고 다시 올린다.

### 분류

| 지적 | 결정 | 반영 |
| --- | --- | --- |
| 기준 무게가 횟수를 반영 못 함(코치 1) | 채택 | 무게 기준을 새 `pctWork` 대신 기존 「추정 1RM 의 %」(pct1rm)로. 퍼센트는 목표 횟수에서 한두 개 남기는 값. 기록이 없으면 첫 작업 세트로 추정해 채우는 기존 흐름 |
| 탑 「최대」와 안내 모순(코치 2) | 채택 | 탑은 3~6회 범위, 「최대」는 드롭 줄만 |
| 5×5 안내가 사실과 다름(코치 3) | 채택 | 「다 성공하면 다음엔 직접 무게를 올려요」 |
| 5×5·역피라미드 웜업 계단(코치 4·8) | 채택 | 5×5 웜업 40·60% + 피더 70%, 역피라미드 피더 75% |
| 피라미드 마지막 세트 실패 확률(코치 5) | 채택 | 줄마다 횟수 범위, 안내 「마지막 세트는 횟수가 줄어도 괜찮아요」 |
| 드롭 사이 휴식 0초·기구 제한(코치 6) | 채택 | 다음 세트가 드롭이면 휴식 타이머를 띄우지 않음, 맨몸도 제외 |
| 드롭 무게를 직전 실제 무게 기준으로(코치 6) | 보류 | 지금 채우기 장치(탑셋 %)는 탑 완료에만 반응한다. 1차는 1RM % 로 두고 사용자가 고친다 |
| 기준 제외 세트(코치 7) | 채택 | 피더를 웜업처럼 다뤄 1RM 추정에서 빠진다(아래 피더 결정) |
| 피더 집계 기준(회귀·데이터 7) | 채택 | 피더 = 준비 세트. 세션에서 `is_warmup` 을 함께 켜서 볼륨·PR·1RM·근육 부하·세트 수에서 빠진다. 표시만 P |
| 섞인 표 반영(데이터 2) | 채택 | 운동 중 바꾸면 그 종목 처방의 모든 줄에 새 방식 표시. 반영은 새 틀 전체(`schemeRows`)를 루틴에 쓴다 |
| 세트 추가·삭제 때 처방 자리(데이터 3) | 채택 | 세트 삭제·추가 때 같은 쓰기에서 처방 줄도 빼고 넣는다. 바꾸기는 한 번의 쓰기 |
| 반영 비교가 처방을 안 봄·교체와 겹침(데이터 4) | 채택 | 비교에 처방 포함, 교체된 줄은 새 종목 기구로 `schemeAllowed` 다시 검사 |
| 코칭 중인 회원의 처방을 기기 값이 덮음(데이터 4) | 보류 | 코칭 권한 상태를 앱이 바로 알 수 없다. 2차에 기본 해제로 |
| 서버 보존 조건(데이터 5) | 채택 | 피더는 코치가 일반으로 보냈을 때만, 최대는 횟수가 빌 때만, 방식은 비었을 때만 되살린다 |
