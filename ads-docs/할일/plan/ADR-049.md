# ADR-049 — 잠금화면 운동 화면을 띄우는 길 = 운동 중 포그라운드 서비스(specialUse · 카드 알림) + 「다른 앱 위에 표시」 허용 시 화면 꺼짐에 직접 시작 · 휴식 끝 시각은 서비스가

> 타입 ADR · 그룹 할일/plan · ADStudio가 `ADR-049.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **informs** → SRS-096, SRS-100
- **supersedes** → ADR-048

## 맥락

SPEC-019(v0.60.0 · 앱 1.3.0)로 잠금화면 위 운동 화면(`src/mobile/android/app/src/main/java/org/tarae/liftgram/lock/LockWorkoutActivity.java`)을 냈다. 그런데 실기기(갤럭시)에서 화면을 껐다 켜도 **여전히 삼성 잠금화면**이 나왔다(사용자 2026-11-03).

원인은 ADR-048이 「포그라운드 서비스 없음」을 택해서 생긴 세 가지 한계다.

- **방송이 늦게 온다**: Android 14+는 뒤에 있는 앱 프로세스를 cached(얼림) 상태로 둔다. 그 상태에서는 동적 리시버의 방송(SCREEN_OFF/ON)을 미루거나 합친다. 그래서 `src/mobile/android/app/src/main/java/org/tarae/liftgram/lock/LockScreenGate.java`가 화면 꺼짐·켜짐을 제때 받지 못한다.
- **뒤에서는 화면을 못 띄운다**: 백그라운드 액티비티 시작(BAL)은 조용히 막힌다. 그래서 직접 시작은 앱을 보고 있던 2초 안에만 된다.
- **전체 화면 알림(FSI)이 막힐 수 있다**: 삼성은 「전체 화면 알림」 허용이나 채널 중요도에 따라 FSI를 알림 줄로만 보여 준다.

## 결정

ADR-048의 화면 구조(showWhenLocked 전용 액티비티 · FSI로 띄우기)는 그대로 둔다. 띄우는 길만 아래처럼 바꾼다.

1. **운동 중에만 포그라운드 서비스** `WorkoutService`를 켠다.

  - 종류: `foregroundServiceType="specialUse"`. 자체 배포라 플레이 심사 문구는 필요 없지만 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`에 용도를 적는다.
  - 포그라운드 알림: 기존 운동 카드(ID 7301)를 그대로 쓴다. 알림이 두 장 생기지 않는다.
  - 시작: 앱이 앞에 있을 때만 시작한다(백그라운드 FGS 시작 금지). 운동 시작·진행 중 스냅샷이 올 때다.
  - 멈춤: 운동 종료(스냅샷 없음), 프로필에서 잠금 운동 화면 끄기, 서비스 시간 초과 때 멈춘다.
  - 효과: 프로세스가 cached가 되지 않아 화면 꺼짐·켜짐 방송이 제때 온다.
2. **서비스가 도는 동안 휴식 끝 시각은 서비스가 지킨다.** 서비스 안의 핸들러와 시간 제한이 있는 PARTIAL_WAKE_LOCK(최대 15분)을 쓴다.

  - `RestShortService`(shortService)는 서비스가 없을 때만 쓴다. 같은 알림 id를 쥔 서비스가 둘이 되지 않게 하려는 것이다.
  - 정확 알람 권한이 있으면 정확 알람이 우선이다.
3. **「다른 앱 위에 표시」(SYSTEM_ALERT_WINDOW)를 허용받으면** 화면이 꺼지는 순간 앱이 뒤에 있어도 운동 화면을 직접 띄운다. 이 허용은 BAL 예외다. 꺼진 화면 뒤에 미리 떠 있다가, 화면을 켜면 바로 보인다.

  - 허용이 없으면 지금처럼 동작한다: 앞에 있던 2초 안이면 직접 시작, 아니면 화면이 켜질 때 FSI.
4. **프로필에서 빠진 허용을 보여 준다.** 「다른 앱 위에 표시」와 「전체 화면 알림」이 빠졌으면 줄로 보여 주고, 누르면 그 설정 화면을 연다.

## 대안

| 대안 | 왜 안 했나 |
| --- | --- |
| ADR-048 그대로(FSI만) | 실기기에서 실패했다. cached 프로세스는 방송부터 못 받는다. |
| 운동 시간 내내 FGS 없이 정확 알람으로 주기적으로 깨우기 | 화면 꺼짐 순간을 알 수 없다. 배터리도 더 쓰고, 알람 권한도 필요하다. |
| `health` 종류 FGS | 활동 인식·센서 런타임 권한이 필요하다. 우리 용도(잠금 화면 조작)와 맞지 않는다. |
| 오버레이 창(TYPE_APPLICATION_OVERLAY)을 잠금화면 위에 그리기 | 오버레이는 키가드 위에 그려지지 않는다. 터치 가로채기라 정책 위험도 있다. |
| 잠금화면 대체 앱(키가드 끄기) | 보안을 낮추고, 기기 관리자 권한이 필요하다. |

## 결과

- 좋아지는 점

  - 화면 꺼짐·켜짐을 제때 받는다.
  - 「다른 앱 위에 표시」를 허용하면 앱이 뒤에 있어도 운동 화면이 뜬다.
  - 휴식 끝 시각도 3분 제한 없이 지켜진다.
- 비용

  - 운동 중 카드가 포그라운드 서비스 알림이 된다. Android 13 이하에서는 밀어 지울 수 없다. 14+에서는 지울 수 있지만, 다음 상태 변화 때 다시 나온다.
  - 휴식 중 wake lock 때문에 배터리를 조금 더 쓴다.
  - 운동이 끝나면 서비스가 멈춘다.
- 플레이 배포 때는 specialUse 용도 설명과 SYSTEM_ALERT_WINDOW 사용을 다시 판단해야 한다. 지금은 자체 배포다.
- ADR-046의 「카드는 포그라운드 서비스 없음」은 이 결정으로 바뀐다. 운동 중에는 서비스가 카드를 쥔다.
