# BS-007 — 미구현·추가 구현 과제 점검 — 장비 리스트·코칭·기획 대조

> 타입 BS · 그룹 할일/plan · ADStudio가 `BS-007.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

## 요약

할 일 #T8의 점검 결과입니다. 결론은 세 가지입니다.

- 장비 리스트는 켜고 끄기는 되지만, 저장한 브랜드가 글 작성에 이어지지 않고 안내 문구가 사실과 다릅니다.
- 코칭은 요청·수락·처방이 동작하지만 동의 안내와 알림이 없습니다. 코치가 회원의 분석 페이지를 보는 화면은 아직 없습니다.
- 기획과 대조하면 가입 동의 기록, 오류 보고, 공유 링크, 푸시, 초기 피드가 빠져 있습니다.

**확인 범위:** 코드와 문서를 읽어 판정했고 앱을 실행하지는 않았습니다. `SRS-021`~`SRS-101`은 코드 참조로 훑었기 때문에 수용 기준을 하나씩 확인한 것은 아닙니다. `SRS-001`~`SRS-020`과 BS-004 원문은 저장소에 없어 PRD와 로드맵의 인용으로 봤습니다.

- **푸시:** 어떤 문서도 출시 게이트로 정하지 않았고, 서비스 워커와 앱 모두 푸시 처리가 없습니다. 소셜 알림을 앱 밖에서 받게 하려면 출시 전에 넣기를 권합니다.
- **코치 분석 화면:** 코칭을 출시의 핵심으로 내세우면 필수, 아니면 뒤로 미룹니다. ADR-051은 코칭 재설계 때 구현한다고만 정했습니다.
- **계정 제재:** 지금은 글을 감출 수만 있습니다(`src/proto/moderation/v1/moderation.proto:48`). 문서 요구는 없고 심사 필수 여부도 미확인이지만, 게시 기능이 있는 앱이라 넣기를 권합니다.

### 코치가 회원의 분석 페이지를 보려면(ADR-051)

**이미 있는 것:** 회원 기록을 내주는 서버 API와 열람 기록(`src/backend/internal/coaching/records.go:68`), 코치 기기에서 계산하는 경로(`src/core/src/domain/summaryRecords.ts:184`).

**없는 것:**

- **화면:** `src/frontend/app/components/analytics/StatsClient.tsx`에 회원을 지정하는 값이 없습니다.
- **데이터 연결:** 분석 코드가 내 기기 DB를 직접 읽습니다(`src/core/src/data/analyticsRepository.ts:5`). 카드도 각자 조회합니다.
- **체중:** 서버가 내주지 않아, 그대로 쓰면 맨몸·어시스트 계산에 코치 체중이 들어갑니다(`src/core/src/data/analyticsRepository.ts:70`).
- **「전체」 기간:** 내주는 범위가 800일이고 페이지 나눔이 없습니다(`src/backend/internal/coaching/records.go:43`). 최고 기록과 정체 종목도 같은 제약을 받습니다.
- **읽기 전용:** 체중 카드에 기록 입력이 있습니다(`src/frontend/app/components/analytics/BodyweightCard.tsx:50`).

**충돌:** ADR-051의 「그대로 본다」와 SRS-048의 「신체정보 제외」가 체중 카드에서 부딪힙니다. 구현 전에 정해야 합니다.
