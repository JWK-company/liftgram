# ADR-047 — 안드로이드 앱 = 새 출시 키 + 사이트 자체 배포(앱 안 업데이트) · PWA → 앱은 패키지 지정 intent 로 일회용 로그인 코드 넘기기 · iOS 는 스토어 출시 뒤

> 타입 ADR · 그룹 할일/plan · ADStudio가 `ADR-047.json`에서 자동으로 만든 읽기용 파일(고치려면 .json 또는 ADStudio에서)

- **informs** → SRS-095, SRS-099

### 맥락

안드로이드 앱 1.0.x·1.1.x는 이 맥의 **디버그 키**로 서명된 APK를 사람이 직접 나눠 설치했다. `~/.liftgram-release/`에 출시 키가 없다. 사용자는 이미 받은 사람이 「업데이트」로 새 앱을 받고, PWA 사용자가 한 번에 전용 앱으로 갈아타기를 원한다(2026-11-03). 플레이 스토어 등록·심사는 아직 안 했다. 안드로이드는 같은 키로 서명된 APK만 덮어쓰고, 스토어 밖 설치는 화면 없이 할 수 없다(시스템 「설치」 확인 한 번).

### 결정

1. **출시(업로드) 키를 새로 만든다** — `~/.liftgram-release/upload.jks`(저장소 밖)와 `upload.properties`. 디버그 키는 이어 쓰지 않는다. 디버그 키는 기기마다 다를 수 있고 공개된 비밀번호라 출시용으로 약하다. 옛 앱 사용자는 **한 번만** 지우고 다시 설치한다. 기록은 서버 동기로 되살아난다(지우기 전 미동기 확인).
2. **자체 호스팅** — 배포 스크립트(`src/scripts/deploy-h2500-3.sh`)가 출시 APK(버전 코드마다 한 번 빌드·맥에 보관)와 `android.json`을 웹 이미지의 `public/downloads/`에 넣어 함께 올린다. 화면이 원격(server.url)이라 업데이트 안내는 웹이 그리고, 받기·확인·설치만 네이티브 플러그인(`LiftgramUpdate`)이 한다.
3. **PWA → 앱 로그인 넘기기** — 로그인한 웹이 일회용 로그인 코드(기존 `IssueLoginCode`)를 받는다. 코드는 `intent://transfer?code=…#Intent;scheme=liftgram;package=org.tarae.liftgram;…` 로 **우리 패키지에만** 넘긴다. 앱은 `/auth/complete?code=`로 착지한다(소셜 로그인과 같은 끝).
4. **iOS는 나중** — App Store·TestFlight만 가능하다. 출시 뒤 따로 한다.

### 대안

- 디버그 키 유지 — 재설치는 없지만 키 관리가 불가능하고 플레이 출시 때 어차피 바뀐다(기각).
- 플레이 스토어 인앱 업데이트 — 가장 매끄럽지만 등록·심사가 먼저다. 출시 뒤 이 길로 옮긴다. 그때 `REQUEST_INSTALL_PACKAGES` 권한은 플레이 빌드에서 빼야 한다(정책).
- 웹 화면 없이 네이티브 업데이트 화면 — 화면을 웹 하나로 두는 ADR-046과 어긋난다(기각).

### 결과

- 출시 키를 잃으면 모든 사용자가 다시 재설치해야 한다 → 키 파일·비밀번호를 사람이 따로 백업한다.
- 앱 링크 검증(`/.well-known/assetlinks.json`)의 인증서 지문(`ANDROID_CERT_SHA256`)을 새 키로 바꾼다.
- APK가 웹 이미지에 실린다(수 MB) — 서비스 워커는 `/downloads/`를 가로채지 않는다.
- 출시 키는 이 판(v3)에서 회전할 수 없다 — 키를 바꾸면 모든 사용자가 다시 재설치해야 한다. 앱 링크 지문(`ANDROID_CERT_SHA256`)에는 새 지문을 **더한다**(옛 지문을 바로 지우지 않는다 — 옛 앱 사용자가 재설치하는 동안).
- 판정의 기대 지문은 앱에 박힌 릴리스 지문(`src/mobile/release-cert.json`)이다. 서버 json이 바뀌어도 서명이 맞는 앱에 재설치를 권하지 않고(minSigned는 지문을 모를 때만), json 지문이 다르면 아무것도 권하지 않는다. 공개 `/app`도 json 지문이 다르면 받기를 숨긴다(REV-013).
- 로그인 넘기기는 웹 세션의 access token 하나로 30일 넘기기 세션을 만든다 — 기존 소셜 연결과 같은 급의 **수용 위험**이다. 넘긴 세션은 「최근 로그인」이 아니라 계정 삭제·첫 비밀번호는 다시 로그인한다(REV-012).
- 같은 기기의 악성 앱이 `liftgram://` 스킴을 가로챌 수 있다 — 코드는 앱 웹뷰의 S256 비밀 없이는 교환되지 않는다. 돌아오는 길을 검증된 https 앱 링크로 바꾸는 것은 다음 판.
