## SPEC-018 Phase 2 — 안드로이드 업데이트 플러그인 구현

### 요약

안드로이드 앱에 웹 다리 `LiftgramUpdate`를 넣었다. 웹 화면이 다리로 하는 일은 넷이다. 서버의 APK를 받고(출처·크기·sha256 확인), 시스템 확인 화면 한 번으로 설치하고, 새로고침 뒤에 상태를 이어 보고, 업데이트가 끝나면 알림과 「업데이트됐습니다」를 한 번 보인다.

설치 직전에는 네이티브가 패키지·서명 집합·버전·바이트 해시를 매번 다시 본다. 웹(원격 JS)이 주는 값은 「무엇을 받을지」 고르는 데에만 쓴다.

에뮬레이터 두 대(API 35·30)에서 확인한 것:

- 출시 키 APK 업데이트 왕복에서 데이터가 유지되고, 하강과 다른 키 서명은 거부된다.
- 계측 시험이 실제 PackageManager로 통과한다.

### 코드 리뷰

REV-011 — 전문가 4명(보안 감사관 · 웹 계약 검토자 · 시험 충분성 검토자 · 안드로이드 설치 검토자), 57건: 채택 51 · 보류 5 · 기각 1.

가장 큰 것은 받기 크기 읽기 결함(받기가 전부 거절됨)이다. 그 밖에 아래를 반영했다.

- 실행기 분리
- 확인 화면 필수
- 옛 브리지 거절
- API 28~32 서명 읽기
- 상태 복구 `state()`
- 닫힌 코드표
- 세션 id
- 전용 FileProvider

반영 뒤 위 시험을 모두 다시 돌렸다.
