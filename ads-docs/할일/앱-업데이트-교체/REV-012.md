## SPEC-018 Phase 3 코드 리뷰 — 웹 → 앱 로그인 넘기기

대상은 SPEC-018 Phase 3에서 바뀐 코드다.

- 백엔드: `src/database/migrations/0022_refresh_token_origin.sql` · `src/database/queries/auth.sql` · `src/backend/internal/auth/account.go` · `src/backend/internal/auth/service.go` · `src/backend/internal/auth/repo.go` · `src/backend/internal/auth/handler_account.go` · `src/backend/internal/oauth/handoff.go` · `src/backend/cmd/server/main.go` · `src/proto/auth/v1/auth.proto`
- 화면: `src/core/src/domain/appContinue.ts` · `src/frontend/lib/native.ts` · `src/frontend/app/app/continue/ContinueClient.tsx` · `src/frontend/app/components/auth/AppContinueEntry.tsx` · `src/frontend/app/auth/complete/CompleteClient.tsx` · `src/frontend/next.config.ts`
- 시험: `src/backend/internal/auth/app_continue_test.go` · `src/frontend/e2e/app-continue.spec.ts`

검토자 넷은 코드를 읽기만 했다. 지적은 반영한 뒤 Go 시험·실 DB 시험·e2e로 다시 확인했다.

### 핵심 지적

- **넘겨받은 세션이 최근 로그인이 아니라는 규칙을 실제 SQL로 보는 시험이 없었다**(시험 H-1 · 백엔드 M-1 · 보안 L-7). 가짜 저장소만 썼다. 그래서 `src/backend/internal/auth/repo.go`의 origin 전달을 빼도 시험이 모두 통과했다.

→ `src/backend/internal/auth/app_continue_pg_test.go`를 새로 썼다(실 DB). 확인하는 것: 가입 계열 login · 넘기기 계열 continue · LastLoginAt 그대로 · `reauth_required` · 회전 뒤에도 그대로 · 다시 로그인하면 풀림 · origin·purpose CHECK. origin 전달을 빼는 변이를 넣어 이 시험이 실패하는 것을 확인했다.

- **콜드 스타트 링크가 로그인 탭의 처리기를 지웠다**(화면 H-1). 앱이 `liftgram://start`로 처음 켜진 뒤 그 링크를 처음 듣는 쪽이 로그인 탭이면 `liftgram://auth` 처리기까지 지웠다. 그래서 첫 소셜 연결·재인증이 조용히 실패했다.

→ 콜드 스타트 재생은 원하는 쪽(`replayLaunch` — 진입 강조·잠금 카드 운동 화면)만 받는다. 한 실행에 한 번이다(sessionStorage). 그래서 새로고침해도 `/workout`으로 끌려가지 않는다(화면 M-2). 로그인 탭은 더 이상 `start`를 듣지 않는다.

- **`liftgram://start` 하나에 뜻이 셋이었다**(화면 M-1 · 보안 L-6). 확인 화면의 「다른 방법으로 로그인」이 앱에서 「PWA에서 바꾸기」 강조를 켰다.

→ 그 링크를 `liftgram://auth?cancel=1`로 바꿨다. 코드가 없어 교환하지 않고 탭만 닫는다. 매니페스트는 바꾸지 않았다.

- **탭을 그냥 닫으면 처리기가 남았다**(화면 M-6 · 보안 M-3 일부). 그 뒤 다른 앱이 밀어 넣은 auth 링크가 화면을 오류 착지로 끌고 갔다.

→ `browserFinished`를 받으면 3초 뒤 처리기를 거둔다. 앱 링크로 닫힐 때 auth가 조금 늦게 올 수 있어서 기다린다.

- **진입 버튼 두 번 누르기**(화면 M-5) → 바쁨 상태를 넣고, 실패하면 문구를 보인다(L-10).
- **「계속」 뒤 앱이 열리지 않으면 다시 누를 길이 없었다**(화면 M-4) → 「앱 열기」 링크를 남긴다. 코드는 60초 동안 유효하다.
- **확인 화면이 캐시된 사용자로 그렸다**(화면 L-4) → 세션 확인(`loading`)을 기다린다.
- **서비스 워커가 `/app/continue`·`/auth/complete`를 셸 캐시에 담았다**(보안 L-2 · 화면 L-11) → `/app`·`/app/`·`/auth/complete`는 워커가 가로채지 않는다.
- **LastLoginAt 조건이 열려 있었다**(백엔드 L-7) → `origin = 'login'`으로 닫고, `refresh_tokens_origin_check`를 넣었다(0022는 아직 운영에 적용 전).
- **DB 장애도 두 번째 소모를 시도했다**(백엔드 L-1) → 첫 소모가 「없음」일 때만 넘기기 코드로 다시 본다.
- **시험이 잡지 못하는 변이**(시험 M-1·M-2·L-8). 사용자 캐시가 있어 착지의 세션 대기를 지워도 통과했다. 화면이 열리자마자 서버를 불러도 통과했다. URL 정규식에 앵커가 없었다.

→ 사용자 캐시를 지운 착지 e2e를 넣었다. 누르기 전 0회·누른 뒤 1회를 센다. 정규식에 앵커를 달았다. 콜드 스타트 넘기기 e2e도 하나 더했다.
