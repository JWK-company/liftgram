### 핵심 지적

- **기록 확인을 건너뛰는 길이 있었다**(보안 H-1·M-1 · 화면 H-1 · 시험 M-2). 바꾸기 시트는 저장된 `open`·`done` 단계를 그대로 복원했다. 그래서 확인 없이 「웹 아이콘 지워도 돼요」가 떴다. 재설치 경로도 옛 앱을 지우기 직전에 다시 확인하지 않았다. 게다가 「기록은 서버에 있어요」라고 단정했다.

→ 단계를 복원하면 바로 다시 확인한다. 실패하면 1단계로 돌아간다. 재설치 「/app 열기」도 누를 때마다 확인한다. 화면에 돌아왔을 때 다시 확인해 실패하면 「웹 앱을 지우지 마세요」를 띄운다. 단정하던 문구(`appDist.bannerReinstallBody`·`appPage.s3`)도 고쳤다. 단계 열쇠는 사용자별로 나눴다(화면 L-6).

- **운동 중에 설치 확인 화면이 뜰 수 있었다**(화면 H-2). 운동이 시작되면 시트가 정리 없이 사라졌다.

→ 띠는 연 순간의 판정 사본으로 시트를 그린다. 운동이 시작되면 `state()`를 보고 받기는 끊고, 기다리던 설치는 `cancelInstall()`로 거둔다.

- **「설치 중」에서 빠져나올 수 없었다**(계약 H-1·H-2 · 화면 M-4). 대체 설치(view)는 결과 이벤트가 없다. 결과를 잃은 세션 설치도 마찬가지로 「기다리는 중」에 갇혔다.

→ 「설치 취소」 버튼을 달았다(`cancelInstall`). 돌아왔을 때(resume) view는 `info()`의 versionCode로, 세션은 `state()`로 판단해 aborted로 돌린다. 30분 지난 설치 표식은 거둔다.

- **받아 둔 파일이 지금 최신판에 묶이지 않았다**(보안 M-2 · 계약 M-3). sessionStorage의 id가 옛 판일 수 있었다.

→ id는 `latest.sha256`과 같을 때만 쓴다. download 결과도 대조한다.

- **웹 판정과 네이티브 서명 판정이 어긋났다**(계약 H-3 · 보안 M-4·L-1). 원격 `minSignedVersionCode`가 서명이 맞는 앱에도 재설치를 권했다. 기대 지문도 json 값으로 대신했다.

→ 기대 지문은 앱에 박힌 `RELEASE_CERT_SHA256`(= `src/mobile/release-cert.json`, 단위 시험이 대조)으로 정한다. `minSignedVersionCode`는 지문을 모를 때만 쓴다. json 지문이 다르면 `json-cert`로 아무것도 권하지 않는다.

- **공개 /app의 지문이 같은 서버의 json 값이었다**(보안 M-3) → json 지문이 릴리스 지문과 다르면 받기를 내지 않고 `appPage.certMismatch`를 보인다.
- **받기 링크가 옛 서비스 워커를 거쳤다**(화면 M-10 · 보안 L-5 · 시험 H-4) → `apkHref()` = `?_rsc=apk`. 옛 워커가 `_rsc` 요청을 건너뛰는 것을 이용한다. 같은 헤더·바이트가 오는지 e2e로 확인했다.
- **업데이트 시트의 경합·이어 보기**(화면 M-1·M-2·M-3·M-5 · 계약 M-1·M-2·M-4 · L-1·L-2). 문제는 다섯이었다: 연타 · 다시 붙으면 100%에서 멈춤 · `state()` 전 버튼 깜빡임 · `notAllowed`를 일반 오류로 다룸 · 다시 해도 같은 실패에 다시 시도 버튼.

→ 바쁨 ref로 연타를 막는다. 받는 중에 다시 붙으면 `state()`를 지켜보다 끝나면 `download()`로 id를 받는다(같은 파일이라 바로 끝난다). 응답 전에는 `loading` 단계로 버튼을 그리지 않는다. `notAllowed`이면 설정 단계로 간다. 영구 실패(signature 등)에는 다시 시도 버튼을 두지 않는다. 사용자가 낸 취소는 오류가 아니다. 다른 세션의 결과는 버린다.

- **기록 확인 판정이 화면에 흩어져 있었다**(시험 H-1 · 화면 M-12 · 보안 L-6) → 순수 함수 `recordCheckVerdict`로 뺐고, 9개 조건을 표로 단위 시험한다. 앞선 동기에 합류했으면 최대 2번 동기한다. 설정 대기를 미동기 기록보다 먼저 본다.
- **시험이 경합하거나 언제나 참이었다**(시험 H-3·M-1). 가짜 다리가 `pending`을 저절로 쐈다. 부정 단언은 「800ms 뒤 0개」였다.

→ 가짜는 더 이상 저절로 쏘지 않는다. 판정 표식(`app-offer-state`의 kind·why)을 기다린 뒤 단언한다.
