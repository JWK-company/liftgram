## SPEC-018 Phase 1 — 버전 원본 · 출시 키 · APK 빌드 · 배포 파이프라인 구현

### 요약

앱 버전의 원본을 `src/mobile/release.json`(1.2.0 / versionCode 3) 하나로 정했다. 새 출시 키(앱 서명 키)를 만들었다.

- 서명 APK 한 벌과 `android.json`을 만드는 단독 스크립트를 썼다. 순서는 키 없는 빌드 → zipalign 16KB → apksigner v2·v3 → 검증 → 깨끗한 커밋만 캐시다.
- 배포 스크립트가 커밋된 사본에서 이 스크립트를 부르고, 웹 이미지에 APK를 싣고, 배포 뒤 끝까지 확인한다.

서비스 워커는 `/downloads/`를 가로채지 않고, 옛 워커가 담아 둔 것을 지운다. Next와 커스텀 서버는 APK·json 헤더와 없는 이름의 404를 맞게 낸다.

### 범위 밖 변경

- `src/frontend/server.mjs`: 스펙 범위표에 없었다. 없는 APK 이름의 404가 APK로 저장되는 문제(REV-010 웹 M-1)를 고치려면 Next 앞단에서 막아야 해서 손댔다.
- `src/.dockerignore`: 스펙 범위표에 없었다. 모바일 빌드 산출물이 이미지 문맥에 들어가는 것을 막았다(REV-010 운영 M-3).
- Phase 2 선행: REV-010 리뷰를 기다리는 동안 `src/mobile/android/app/src/main/java/org/tarae/liftgram/update/` 파일들과 매니페스트·등록·백업 규칙을 먼저 썼다. 컴파일과 JUnit 6건을 통과했다. Phase 2 EXE에서 마저 검증한다.
