### 핵심 지적

- **받기가 전부 거절됐다**(시험 H-1). 크기를 `call.getLong("size")`로 읽었는데, 브리지는 작은 수를 Integer로 풀어 줘서 늘 null이 됐다. 그래서 모든 받기가 `invalid`로 끝났다.

→ `ApkCheck.parseSize`가 Integer·Long·Double을 모두 받는다. 정수인 양수, 200MB 이하만 통과한다. 실제 JSONObject 형으로 JUnit을 돌렸다.

- **받는 동안 다른 메서드가 줄을 섰다**(계약 H-1 · 안드로이드 M-3 · 보안 M-4). 실행기가 하나라 `info()`·`openInstallSettings()`가 받기가 끝날 때까지 막혔다. `busy`도 실제로는 나오지 않았다. `handleOnDestroy`의 `shutdownNow()` 뒤에는 메인 스레드에서 `RejectedExecutionException`이 났다.

→ 실행기를 둘로 나누고 static으로 올렸다(받기 DL 한 줄 · 나머지 IO). 받는 중이면 줄 세우지 않고 바로 `busy`를 준다. 해시가 틀린 sha256은 10분 동안 다시 받지 않는다. 설치가 진행 중이면 다른 파일을 지우지 않는다.

- **원격 화면이 확인 없이 설치·재시작을 일으킬 수 있었다**(보안 M-1 · 안드로이드 M-1 · 계약 M-1). `USER_ACTION_NOT_REQUIRED`는 권한이 없으면 아무 일도 하지 않고, 권한이 생기면 확인 없이 프로세스가 죽는다.

→ `USER_ACTION_REQUIRED`로 바꿨다. 설계대로 언제나 시스템 확인 화면이 한 번 뜬다.

- **옛 브리지면 iframe의 호출도 통과한다**(보안 M-2).

→ 플러그인이 `WEB_MESSAGE_LISTENER`를 지원하는지, 그리고 `isUsingLegacyBridge()`가 아닌지 확인한다. 하나라도 어긋나면 모든 호출을 `origin`으로 거절한다. `src/mobile/capacitor.config.ts`에 `android.useLegacyBridge:false`를 명시했다(출시 APK의 `assets/capacitor.config.json`에서 확인).

- **Android 9~12L에서 받은 APK의 서명을 못 읽을 수 있다**(안드로이드 H-1 · 시험 M-2).

→ 28 이상에서는 `GET_SIGNING_CERTIFICATES`에 `GET_SIGNATURES`도 함께 준다. 고르는 규칙은 `ApkCheck.pickSigners`(JUnit)로 옮겼다. signingInfo가 비면 옛 signatures를 쓴다. → 계측 시험 `src/mobile/android/app/src/androidTest/java/org/tarae/liftgram/update/UpdateInstallerDeviceTest.java`가 **API 35와 API 30 에뮬레이터 모두에서 5/5 통과**했다. 출시 서명 APK의 서명자 읽기, 실제 판정, 세션 쓰기·취소를 본다.

- **화면을 새로 고치면 다시 알 길이 없었다**(계약 H-2·M-7).

→ `state()`가 받는 중(id·받은 양), 설치 중(판·세션 id·시각), 확인 화면 대기, 마지막 결과를 준다. 마지막 결과는 리스너를 달기 전에 온 이벤트도 남긴다.

- **실패 코드가 웹 문구표와 1:1이 아니었다**(계약 H-3 · 보안 L-7).

→ 닫힌 표 `ApkCheck.ERROR_CODES` 16개를 정했다. 그 밖의 값은 `failure`로 바꾼다. 뜻이 겹치던 것도 나눴다.

- `invalid`는 인자 형식에만 쓴다. 깨진 파일은 `missing`, 허용 꺼짐은 `notAllowed`, 사용자 취소는 `cancelled`다.
- 시스템 메시지 원문과 예외 이름은 웹으로 보내지 않는다.

- **옛 세션의 결과가 새 시도처럼 보였고, 확인 화면이 두 번 떴다**(계약 H-4 · 안드로이드 M-2).

→ 설치 전에 우리가 만든 끝나지 않은 세션을 모두 abandon한다. 세션 id는 표식에 적는다. 리시버는 지금 세션이 아닌 결과를 버린다. `installResult`에 `sessionId`를 싣는다. 맡겨 둔 확인 화면은 30분 안이고 같은 세션일 때만 띄운다.

- **확인 화면을 못 띄우면 failure 뒤에 pending이 왔다**(계약 H-5).

→ `offerConfirm`이 성공 여부를 돌려준다. 실패하면 pending 없이 failure 하나만 보낸다.

- **확인 화면 Intent를 검증 없이 실행했다**(보안 L-2 · 안드로이드 L-1 · 시험 M-3).

→ `IntentCompat.getParcelableExtra`로 API 33 버그를 피한다. 대상이 시스템 앱인지 확인하고, URI 권한 위임 플래그를 지운다.

- **FileProvider가 캐시 전체와 외부 저장소를 덮었다**(보안 M-3 · 안드로이드 L-2).

→ 업데이트 전용 `src/mobile/android/app/src/main/java/org/tarae/liftgram/update/UpdateFileProvider.java`(`${applicationId}.updates`)를 만들었다. `src/mobile/android/app/src/main/res/xml/update_paths.xml`은 `cache/updates/`만 덮는다. 대체 설치(view)는 시스템 설치기에만 `setPackage`로 권한을 준다.
