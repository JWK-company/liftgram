## SPEC-018 Phase 3 — 로그인 넘기기(앱이 시작) · 백엔드 구현

### 요약

로그아웃된 안드로이드 앱에 「웹에서 쓰던 계정으로 계속」을 넣었다. 누르면 크롬 탭이 확인 화면(`/app/continue`)을 연다. 크롬의 웹 세션으로 「계속」을 누르면 서버가 60초짜리 넘기기 코드를 맡기고 `liftgram://auth`로 돌려준다. 그 코드는 앱 웹뷰만 가진 S256 비밀(v)로만 교환된다.

넘겨받은 세션 계열은 `origin='continue'`로 적는다. 이 계열은 「최근 로그인」으로 치지 않는다. 그래서 계정 삭제·첫 비밀번호 설정은 다시 로그인해야 한다.

앱 스킴 링크는 디스패처 하나가 갈래(auth·workout·start)로 나눠 보낸다.

### 코드 리뷰

REV-012 — 전문가 4명(인증 보안 감사관 · 백엔드·DB 검토자 · 화면·앱 흐름 검토자 · 시험 충분성 검토자), 54건: 채택 23 · 보류 30 · 기각 1.

가장 큰 둘을 반영했다.

- 실제 SQL을 보는 시험이 없었다 → 실 DB 시험을 넣고, 변이로 시험이 결함을 잡는지 확인했다.
- 콜드 스타트 링크가 로그인 탭 처리기를 지웠다 → 재생은 원하는 쪽만, 한 실행에 한 번만.

그 밖에 반영한 것:

- `start` 링크의 뜻 겹침을 풀었다.
- 탭 닫힘 정리 · 진입 바쁨 상태 · 「앱 열기」 링크
- SW 예외
- 닫힌 SQL 조건과 CHECK
- e2e 보강
