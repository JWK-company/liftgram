## SPEC-018 후속 픽스 코드 리뷰 — 앱 안 업데이트가 「취소했어요」로만 끝날 때의 우회 길

### 배경

- 실기기(갤럭시)에서 「앱 설치 파일 업데이트」가 몇 번을 눌러도 `aborted`(「취소했어요」)로 끝났다. 그래서 설치된 앱이 1.2.0에 머물렀다(2026-11-04 사용자 캡처).
- 그 결과 1.3.0·1.4.0(SPEC-019·SPEC-020)의 잠금화면 기능은 실기기에 한 번도 들어가지 않았다.
- 기기의 네이티브 코드(1.2.0)는 앱을 새로 설치하지 않으면 바꿀 수 없다. 그래서 서버에서 바로 바뀌는 **웹 화면만** 고쳤다(웹 v0.61.1).

### 바꾼 것

- `src/frontend/app/components/appdist/AppUpdateSheet.tsx`:

  - `aborted`·`failure`·`timeout`일 때도 「다른 방법으로 설치」(view)를 연다. 세션당 한 번이다.
  - `aborted`·`blocked`·`failure`·`timeout`·`expired`일 때 「브라우저로 받아 설치」를 보인다.
  - 원인 코드와 판정 출처(result·resume·call·restore·view)를 캡션으로 보인다.
- `src/core/src/i18n/locales/ko.ts`·`src/core/src/i18n/locales/en.ts`: `appDist.err.aborted` 문구를 바꾸고 `errDetail`·`browserDownload`·`browserHint` 키를 더했다.
- `src/frontend/lib/i18n.ts`: 프로필 웹 번들 줄 이름을 「화면 버전」·「화면 업데이트」로 바꿨다. 「앱 설치 파일」(안드로이드 앱) 줄과 헷갈리지 않게 하려는 것이다.
- `src/frontend/e2e/app-distribution.spec.ts`·`src/frontend/e2e/manual-update.spec.ts`: 시험을 보강하고 바뀐 문구에 맞췄다.

### 패널 구성

- 모바일 웹 화면·안드로이드 설치 흐름 리뷰어 1명(Patch급)
