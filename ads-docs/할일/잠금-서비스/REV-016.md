## 패널 구성

Feature 등급이라 전문가 3명이 각자 따로(병렬로) 검토했다. 대상은 SPEC-020 v1과 ADR-049다.

| 역할 | 관점 |
| --- | --- |
| 안드로이드 플랫폼 전문가 | FGS·백그라운드 액티비티 시작(BAL)·키가드·삼성 One UI, 원인 진단이 맞는가 |
| 수명주기·동시성 검토자 | 서비스 시작·멈춤 경합, 휴식 타이머, wake lock, 카드 정리 |
| 모바일 UX·웹 다리 검토자 | 프로필 진단 줄 문구·조건, 설정 다녀오기, e2e, 실기기 확인 목록 |

## 핵심 지적

- **원인 진단에 증거가 없다**(플랫폼 H-1·H-2)

  - 「앞에 있던 2초 안 직접 시작」은 화면이 잠들면 TOP_SLEEPING이라 이미 막혔을 수 있다.
  - 그래서 오버레이 허용을 주 경로로 두고, 실기기에서 원인을 볼 **진단 기록**을 넣는다.
- **BAL은 예외 없이 조용히 막힌다**(플랫폼 H-3 · 수명 H-2): try/catch로는 실패를 알 수 없다. 휴식 끝 직접 시작은 1.5초 뒤 떠 있는지 확인하고, 없으면 FSI로 넘어간다.
- **서비스 시작 요청과 onStartCommand 사이의 멈춤 요청이 사라진다**(수명 H-1): `desired` 깃발을 두고 onStartCommand에서 다시 확인한다.
- **시스템 종료 뒤 다시 시작하는 고리**(수명 H-3): `blocked` 깃발을 두고, 다음에 앱이 앞에 올 때 푼다.
- **같은 알림 id를 두 FGS가 쥔다**(플랫폼 H-5 · 수명 M-7): shortService가 돌면 먼저 끝내고, 그 onDestroy가 부르는 refresh에서 시작한다.
- **진단 줄 둘이 비슷해 헷갈린다**(UX H-1·H-2): 보조 글로 구별하고, 오버레이 허용이 왜 안전한지 문구에 넣는다.
