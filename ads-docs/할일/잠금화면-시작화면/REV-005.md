### 핵심 지적

- **출처가 한 값이라 백오프가 「앱 열기」에 갇혔다**(도메인·저장소 H-1): 칸 중 가장 약한 출처를 한 값으로 저장해, 처방 채우기가 무게를 올려도 횟수 칸의 `default`가 남아 탑셋→백오프 주 흐름이 잠금에서 막혔다. → 칸별 출처 `"무게,횟수"` 부호화 + 스냅샷의 앱 열기 판정을 시뮬레이션한 출처로.
- **채우기 실패가 완료 전체를 깨뜨렸다**(화면 H-1 · 저장소 M-1 · 도메인 L-2): 옛 화면은 try/catch로 삼키던 채우기 실패가 새 흐름에서 throw → 휴식·PR·입력 비우기가 빠졌다. → 흐름이 `fillError`로 돌려주고 완료 실패만 던진다.
- **짝짓기가 화면(짝 키)과 잠금(위치)에서 달랐다**(도메인 M-3): 탑셋이 섞이면 같은 세션 안에서 짝이 바뀌었다. → 잠금도 화면의 `roundKeyOf` 짝 키로(스펙 표 수정).
- **테스트가 주장만 했다**(테스트 H-1·H-2·M-1): 시뮬레이션=drain DB 테스트가 1/5 경로, 출처 전파 DB 검증 없음, 이관이 실제로 돌았는지 미증명. → 메모리 DB 테스트 9개(5경로+lb·한쪽·pct1rm·휴식·사람이 고친 세트), 이관은 문서에 칸이 생기고 드라이버 버전 27까지 단언.
