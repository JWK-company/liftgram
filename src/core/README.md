# core — 도메인 계산 · 정적 데이터 · 문자열 (ADR-032)

**이 디렉터리의 `src/`는 생성물이다. 여기서 고치지 않는다.**
원본은 `app/src/` 이고, `make sync-core` 가 복사한다. 어긋나면 `make core-check` 가 검증에서 실패시킨다.

```
원본            app/src/{domain,data,i18n}      ← 여기를 고친다
   │  make sync-core
   ▼
생성물          src/core/src/{domain,data,i18n} ← 여기는 읽기만
```

## 왜 이렇게 두는가

제품의 계산 규칙(PR·볼륨·1RM·처방·주간스케줄·변형버킷)은 **오프라인에서도 돌아야 한다**(ADR-002).
그래서 이 계층은 Go로 옮기지 않고 TypeScript로 남긴다 — 백엔드에 다시 구현하면 같은 규칙이
두 언어에 두 벌 생기고, 둘은 반드시 갈라진다(ADR-032의 근거).

이행 기간에는 `app/`(Expo Web)과 `src/`(Next)가 **같은 규칙을 공유해야** 하는데, 손으로 두 번
적으면 그 순간 갈라진다. 그래서 한쪽을 원본으로 못 박고 나머지를 파생시킨다 —
운동 카탈로그 시드를 `make gen-exercise-seed` 로 파생시킨 것과 같은 원칙이다.

`app/` 이 은퇴하는 날 이 디렉터리가 원본이 되고, 동기 스크립트와 검사는 사라진다.

## 무엇이 들어 있나

| 경로 | 내용 | 비고 |
|------|------|------|

| `src/data/seed/` | 운동 카탈로그 시드 336종 · 대체운동 큐레이션 | 상수 배열 |
| `src/data/exerciseMedia*.ts` | 종목별 시연 이미지·스텝 매핑 | 상수 맵 |
| `src/i18n/locales/` | ko · en 문자열 | 상수 맵 |
| `src/db/` | 로컬 저장소 — 스키마·마이그레이션·모델 7종·구독 훅 | WatermelonDB. **브라우저 전용** |

## 옮기면서 바뀌는 것 두 가지

원본과 파생물이 **일부러 다른** 자리는 여기뿐이고, 둘 다 기계가 매번 적용·검증한다.

| 무엇 | 왜 |
|------|-----|
| `db/adapter.web.ts` → `db/adapter.ts` (네이티브 `adapter.ts` 는 안 옮김) | app은 Metro가 웹 빌드에서 `.web.ts` 를 자동으로 골라 준다. Next엔 그 해석이 없어 **웹판을 정본 이름으로** 옮긴다 — 그래야 `database.ts` 를 한 글자도 고치지 않는다 |
| `db/models/*.ts` 의 `@text('x') name!: T` → `@text('x') declare name: T` | Babel(app)은 선언만 있는 필드를 지우지만 **SWC(여기)는 define 필드로 낸다** → own 프로퍼티가 데코레이터 접근자를 가려 모델이 전부 undefined가 된다. `declare` 면 TypeScript가 코드를 아예 내지 않아 두 툴체인 모두에서 산다 |

두 번째가 특히 위험한 이유: **조용히 틀린다.** 저장은 되는데(원시 행은 채워짐) 읽으면 undefined이고,
타입 검사도 빌드도 통과한다. 그래서 `/diag/db` 화면이 왕복을 실제로 해 보고, e2e(`local-db.spec.ts`)가
그 판정을 매번 확인한다. 원본에 `declare` 를 넣는 편이 더 깔끔하지만 app의 Babel 플러그인 순서가
이를 거절한다(실측) — 살아 있는 앱의 빌드 설정을 새 스택 때문에 흔들지 않기로 했다.

## 테스트

```bash
make test        # Go 테스트 + 이 패키지의 도메인 테스트 154건
```

테스트가 함께 옮겨 오는 것이 이 이관의 핵심이다 — **이전이 곧 검증**이다.
재작성했다면 테스트도 재작성 대상이 되어 "같은 동작인가"를 증명할 수단이 사라진다.
