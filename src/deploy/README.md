# 배포 — 개발 단계는 무료, 정식 배포는 유료로

## 지금(개발 단계) — 완전 무료

| 구성요소 | 무엇을 쓰나 | 비용 |
|---|---|---|
| 화면 + API | **Render 무료 웹 서비스 1개** (합본 이미지 — Dockerfile의 `combined`) | 0 |
| PostgreSQL | **Neon 무료** (0.5GB, 기한 없음) | 0 |
| Redis | **쓰지 않는다** (`REALTIME_BUS=memory`) | 0 |
| 사진·미디어 | 기본은 **컨테이너 디스크**(무료 티어는 영구 디스크가 없어 재배포마다 사라진다) · 남기려면 Cloudflare **R2 무료 10GB** | 0 |

절차: Render → New → Blueprint → 이 저장소 → `src/deploy/render.yaml` → Apply →
대시보드에서 `DATABASE_URL`(**새** Neon 데이터베이스)과 `APP_URL`을 입력.

**감수할 점**: Render 무료는 15분간 요청이 없으면 잠들고, 다시 깨는 데 수십 초 걸린다.
개발 단계에서는 괜찮고, 유료로 올리면 그대로 사라지는 제약이다.

### 사진을 오래 남기려면 (R2)

무료 티어에는 영구 디스크가 없다 — `STORAGE_PROVIDER=disk`면 **재배포·슬립 복귀마다 올린 사진이 사라진다**
(지금 살아 있는 옛 배포도 같은 조건이라, 이 상태 자체는 파리티다).

남기려면 Cloudflare R2에서 **새 버킷**을 만들고(옛 배포와 섞지 않는다) 대시보드 Environment에 넣는다:

| 키 | 값 |
|----|-----|
| `STORAGE_PROVIDER` | `s3` |
| `S3_ENDPOINT` | `https://<account_id>.r2.cloudflarestorage.com` |
| `S3_BUCKET` | 새 버킷 이름 |
| `S3_ACCESS_KEY_ID` · `S3_SECRET_ACCESS_KEY` | R2 API 토큰 |

버킷은 **공개로 열지 않는다.** 사진은 우리 서버가 `/media/file/<key>`로 대신 내보낸다 —
그래야 내려간(모더레이션) 사진의 바이트도 실제로 막히고, 저장소를 바꿔도 이미 올라간 글의 주소가 살아 있다.
설정이 비어 있으면 **부팅이 멈춘다**(조용히 디스크로 떨어지면 사진이 사라지는 걸 아무도 모른다).

**슬립도 피하고 싶다면**: Oracle Cloud Always Free VM(ARM·기한 없음)에 `compose.yaml`을
그대로 올리면 상시 무료로 돌릴 수 있다. 대신 TLS·방화벽·백업을 직접 봐야 한다.

> 무료 티어 조건은 자주 바뀐다. 배포 직전에 각 서비스의 현재 정책을 확인할 것.

## 정식 배포로 갈 때

합본 이미지를 **쓰지 않는다.** `frontend`·`backend` 타깃을 따로 띄우고(독립 스케일),
인스턴스가 둘 이상이 되는 순간 `REALTIME_BUS=redis`로 바꾼다 — 메모리 버스는 프로세스 안에서만
전파하므로, 인스턴스가 늘면 다른 인스턴스의 구독자에게 변경이 도달하지 않는다.

## 옛 배포와의 관계

저장소 루트의 `render.yaml`은 **지금 살아 있는** 옛 백엔드(`server/`, NestJS)다.
파리티가 될 때까지 두 배포는 함께 떠 있고, 서로의 데이터베이스를 공유하지 않는다.
데이터 이관은 전환 시점에 명시적으로 한다.
