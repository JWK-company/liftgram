경쟁 앱 실측 · 2026-10-27

openGym 대조 조사

영상(GitHub 트렌딩 Top 10, 10월 1주)에 나온 openGym을 웹 데모로 직접 돌려 보고, 소스 저장소를 받아 읽고, 리프트그램 코드와 기능 단위로 맞대 봤습니다. 둘 다 Claude Code로 만든 웨이트 기록 앱이지만 겨냥하는 사람이 다릅니다.

한 줄 결론

  • openGym은 "데이터는 내 것"을 내건 혼자 하는 파워유저용 기록기입니다. 셀프호스팅, 계정·광고·추적 없음, 근육 지도와 프로그레션 규칙, 노력도(RIR) 분석이 강점입니다.
  • 리프트그램은 사람이 함께 하는 한국어 운동 앱입니다. 피드·DM·헬스장·P2P 코칭, 스무고개 종목 찾기, 변형 칸 모델은 openGym에 아예 없습니다.
  • 그대로 가져올 만한 것은 RIR 입력과 노력 분석, 근육 지도, 체중 추세, 코치에게 보내는 성과 리포트, 타 앱 기록 가져오기입니다. AI 코치와 자동 처방은 우리 방향(코칭은 사람이 한다)과 맞지 않아서, 승인 카드와 되돌리기라는 UX 패턴만 빌려 오는 걸 권합니다.

02 · 특장점

왜 인기를 끌었나

데이터 주권이 곧 마케팅 self-host

Strong·Hevy가 구독으로 밀어붙이는 시장에서 "docker compose up 한 줄, 내 폴더에 저장, 구독·광고·추적 없음, AGPL"을 내걸었습니다. 셀프호스팅 커뮤니티(r/selfhosted 계열)가 퍼뜨린 구조입니다. 폰 앱만 쓰면 서버도 필요 없습니다.

운동이 알아서 시작된다 guided

홈에서 오늘 루틴 → 체중 체크인 → 바로 시작. 지난 기록과 프로그레션 규칙으로 무게가 미리 채워져(데모: 지난번 65kg×10 → 오늘 70kg) 세트마다 체크만 하면 됩니다.

근육 지도가 모든 곳에 body map

플랜 목록, 오늘 세션, 운동 중 칩 끝, 통계까지 앞뒤 인체 그림이 붙습니다. 통계에서는 균형·피로·근력 세 관점과 "이번 주 안 한 근육" 목록을 보여 줍니다.

규칙이 투명한 프로그레션 progression

루틴마다 선형, Greyskull LP, 이중 진행, 시간 진행 중 하나를 고르고 운동별로 덮어씁니다. 목표 무게마다 근거를 표시하고, 정체가 이어지면 디로드합니다. 기구의 실제 무게 단계(웨이트 스택)도 입력할 수 있습니다.

노력도까지 기록 RIR/RPE

세트마다 "몇 개 더 할 수 있었나"를 6단계로 고르는 시트가 있고, 통계에서 평균 RIR, 주별 추이, 실패 근접 분포를 보여 줍니다. 무게만 보던 진척에 강도라는 축을 하나 더한 셈입니다.

갈아타기 쉬움 import

FitNotes, Strong, Hevy, Gravl CSV와 Apple Health 체중, Hevy API 직결까지 지원합니다. 기존 앱 사용자가 기록을 잃지 않고 넘어올 수 있습니다. 여러 번 가져와도 중복이 생기지 않습니다.

AI는 켜야만 동작 opt-in AI

AI 코치는 기본 꺼짐이고 제공자(Anthropic, OpenAI, Ollama 등)를 직접 고릅니다. 무엇을 보내는지 동의 화면에 적어 두고, 제안은 체크박스 카드로 받아 승인한 것만 반영하며 한 번에 되돌릴 수 있습니다. 읽기 전용 MCP 서버로 Claude Desktop에서 내 기록을 질문할 수도 있습니다.

공개 개발과 빠른 릴리스 build in public

1~2주 간격으로 릴리스하고, 사용자 말투로 쓴 체인지로그와 로드맵, Discord, 외부 PR을 받는 "커뮤니티 릴리스"를 운영합니다. CLAUDE.md에 Claude Code로 개발한다고 밝히고, 검수와 출시는 사람이 맡는다는 점도 분명히 해 둡니다.

05 · 추천

가져오면 좋은 기능

"우리 방향(사람이 코칭하는 소셜 운동 앱)에 맞는가"와 "이미 있는 데이터로 싸게 되는가"를 기준으로 순서를 매겼습니다.

바로 할 만함 · 방향과 맞고 데이터도 있음
1

세트 RIR 입력과 노력 분석

스키마에 rpe 컬럼이 이미 있는데 입력하는 곳이 없습니다. openGym처럼 쉬운 말로 설명한 6단계 시트(0 실패, 1 하나 더, 2, 3, 4+ 쉬움)를 기본 꺼짐 옵션으로 붙이면 됩니다. 쌓이면 통계에 평균과 분포를 보여 주고, 트레이너가 회원의 강도를 보는 근거로 피드·코칭 화면에도 쓸 수 있습니다.

openGym 실측Task · UI + 통계 1블록
2

근육 지도: 세션 미리보기와 주간 균형

카탈로그에 주·보조 근육 열이 있습니다. 앞뒤 인체 SVG 한 벌(근육별 path)을 만들면 루틴 카드, 운동 중 칩, 통계의 "이번 주 안 한 근육"에 재사용할 수 있습니다. 보조 근육 가중치 0.4는 openGym 기본값을 참고하면 됩니다. 피드 오운완 카드에 붙여도 잘 보일 것 같습니다.

openGym 실측Feature · SVG 자산 필요
3

트레이너에게 보내는 성과 리포트

openGym은 "Frame it, print it or send it to your coach"라며 기간별 PDF를 만듭니다. 우리는 코치가 앱 안에 있으니 PDF보다 기간 요약 카드를 코치 DM이나 코칭 화면으로 보내는 쪽이 더 자연스럽습니다. 총량, 새 기록, 종목별 추이, 노력(1번이 되면)을 담으면 됩니다. P2P 코칭 방향과 가장 직접 맞닿는 항목입니다.

openGym 실측Task~Feature
4

체중 체크인과 추세·목표 차트

지금 체중은 볼륨 계산용 값 하나뿐입니다. 시작 전에 건너뛸 수 있는 체크인을 넣고 이력 테이블과 목표선 차트(주간 변화율)를 더하면, 다이어트하는 사용자와 트레이너 둘 다 매일 열어 볼 이유가 생깁니다.

openGym 실측Feature · 스키마 1테이블
5

Strong·Hevy CSV 가져오기

갈아타는 데 가장 큰 장벽은 쌓아 둔 기록입니다. 이름 매칭은 이미 있는 별칭과 검색(초성·NFKC) 위에서 하고, 못 맞춘 이름은 커스텀 종목으로 만들고, 가져오기 전에 요약을 보여 주고, 여러 번 돌려도 같은 결과가 나오게 하는 방식이 openGym 사례입니다. 이관 스크립트를 만들며 쌓은 멱등 노하우를 그대로 쓸 수 있습니다.

문서 확인Feature
검토 후 · 가치는 크지만 방향 판단 필요
6

프로그레션 규칙 선택, 근거 표시, 디로드

BS-004 v2에서 알고리즘 자동 처방은 빼기로 했습니다. 그래서 openGym처럼 앱이 정하는 방식이 아니라 트레이너나 본인이 루틴에 규칙을 지정하는 형태(선형, 이중, 시간)를 권합니다. 이미 있는 detectStall은 "3회 정체, 코치에게 물어보기" 알림 정도로 화면에 연결하면 됩니다.

방향 충돌 주의Feature
7

제안은 체크박스 카드로, 승인 후 반영, 한 번에 되돌리기

AI 코치 자체는 빼고 이 UX만 가져옵니다. 트레이너가 회원 루틴 수정안을 보내면 회원이 항목별로 고르고, 마지막 변경은 되돌릴 수 있게 하는 방식입니다. 우리 "운동 완료 시 루틴 변경점 선택 반영"과 같은 컴포넌트를 쓸 수 있습니다.

문서 확인Feature
8

기구 웨이트 스택

헬스장 머신은 2.5kg 단위로 딱 떨어지지 않습니다. 변형 칸의 브랜드(기구) 단위로 실제 무게 목록을 저장하면 ±버튼과 제안 무게가 그 값에만 떨어집니다. 헬스장·장비 기능과 묶으면 같은 헬스장 회원끼리 공유할 수도 있습니다.

9

로테이션 일정, 드롭세트·레스트포즈·피라미드

요일이 불규칙한 직장인에게는 A, B, C를 순서대로 돌리는 방식이 더 잘 맞습니다. 세트 강도 기법은 세트 메뉴 하나에 모으는 openGym 방식이 화면을 덜 어지럽힙니다.

openGym 실측Task × 2
하지 않거나 나중에

권하지 않음

  • AI 코치 본체: 코칭은 사람이 한다는 결정과 충돌합니다. 의료·웰니스 카피 게이트(SRS-015) 부담도 큽니다.
  • 셀프호스팅과 패스키 중심 설계: 우리 사용자층의 수요가 아닙니다.
  • 종목 5,632개 대량 도입: 영문 데이터셋 이름이 그대로 보이는 게 저쪽 약점이기도 합니다. 미디어 라이선스도 따로 붙습니다. 정리된 480행 + 변형 칸이 오히려 차별점입니다.

나중에 (네이티브가 필요하거나 니치)

  • 헬스장 도착 알림(지오펜스), 워치, 위젯, Live Activity: 웹에서는 제약이 큽니다.
  • 훈련일·놓친 운동 푸시(말투 3종): 웹 푸시부터 깔아야 합니다.
  • MCP 서버, 구조 균형 비율: 파워유저용이라 우선순위가 낮습니다.
06 · 일하는 방식

같은 Claude Code, 다른 점

저쪽에서 배울 것

  • 체인지로그를 사용자 말투로 씁니다("Sorry about that one."). 릴리스 노트가 그대로 홍보물이 됩니다.
  • 공개 로드맵, Discord, 외부 PR 묶음 릴리스로 사용자가 기여자가 됩니다.
  • 첫 사용 힌트를 한 번만 띄우고("Psst: swipe a set"), 기능은 대부분 기본 꺼짐으로 둬서 화면을 조용하게 유지합니다.
  • "Claude Code로 만들고 검수와 출시는 사람이 한다"를 문서에 밝혀서 신뢰를 얻습니다.

이미 우리가 앞선 것

  • 요구에서 설계, 코드까지 이어지는 추적(PLM, @plm)과 /qa 전문가 리뷰 단계가 있습니다.
  • 오프라인 우선 동기와 데이터 손실 복구 경험, 매일 백업이 있습니다.
  • 소셜과 코칭이라는, 혼자 쓰는 기록기가 따라오기 어려운 네트워크 효과가 있습니다.
07 · 방법과 한계

어떻게 조사했나

한 것

  • 웹 데모 실행: Chrome DevTools, 390×844 모바일 에뮬레이션, 13개 화면 캡처
  • 소스 저장소 얕은 복제: README, ROADMAP, CHANGELOG v1.4.3, CLAUDE.md, 테스트 수
  • 공식 문서 전수 열람: opengym.ch/docs
  • 리프트그램 대조: src/의 core, frontend, backend 키워드 grep과 해당 파일 확인

못 한 것

  • APK와 iOS 앱 설치: 이 환경에 실기기가 없습니다. 워치, 위젯, 지오펜스, 알림은 문서로만 확인했습니다.
  • AI 코치는 동의 화면과 목표 설문까지만 봤습니다. 데모에는 연결된 제공자가 없습니다.
  • 셀프호스팅 동기, 관리자 대시보드는 실행하지 않았습니다.
