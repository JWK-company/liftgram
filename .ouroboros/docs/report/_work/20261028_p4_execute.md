## 설계 판단

### 1. 안전망 = lokijs 패치(트랜잭션 안 거부)
- 옵션이 있을 때만 동작, 없으면 원래 코드 그대로(가드 DB·테스트 메모리 DB 는 옵션 없음).
- `saveDatabase` 진입: `isSealed()` 면 IDB 를 열지도 않고 `setTimeout` 으로 `LOKI_SEALED` 오류 콜백(getLokiCopy 안 부름 → dirty 보존).
- `getLokiThenSave` 불일치 분기: `rejectForeignWrites` 면 slow path 대신 `tx.abort()` + `LOKI_STALE`(prev·disk versionId 실음) + `onForeignWrite()`. 콜백 한 번 보장 — 거부 모드에서만 `finish` 를 idempotent 로 하고 abort 이벤트에도 같은 오류를 넘긴다. 비교와 중단이 같은 readwrite tx 안이라 경합 창이 없다(동시 저장 테스트로 확인 — 하나만 이기고 slow path 0회).
- `deleteDatabase`: 봉인 탭은 공유 DB 를 지우지 못한다(`{success:false}`) — 봉인 탭의 계정 전환 리셋이 다른 탭 기록을 지우는 경로를 막는다.
- `onDidOverwrite` 는 거부 모드에서 불리면 불변식 위반으로 console.error.

### 2. 모듈 수준 문(`core/src/db/writeGate.ts`)
- 상태는 `globalThis.__liftgramWriteGate`(모듈이 두 번 평가돼도 하나). `sealLocalDb(reason)` 은 되돌릴 수 없다(새로고침만 푼다). 이유: `stale`·`versionchange`·`writer_lost`·`import_elsewhere`.
- 같은 옵션 객체가 Watermelon `extraIncrementalIDBOptions` → 리셋 때 `newLoki(this.options)` 로 새 어댑터에 다시 들어가므로, 리셋 뒤 새 Loki 도 같은 문을 본다(단위 테스트로 확인).
- `database.write` 문: 봉인·넘겨주기 중이면 `LocalDbSealedError` 로 거부(재검토 L-3 — 반쯤 된 다단계 쓰기·봉인 탭의 `unsafeResetDatabase` 차단). 장벽은 원래 write 로(문을 거치지 않음).
- flush 결과에 `"sealed"` 추가. `flushLocalDb()` boolean 은 sealed 에서도 true(이동용 90여 호출부는 덮개가 막으므로 무해 — 주석). 디스크 확인이 필요한 곳(prefs 대기 표식 · appUpdate · 백필 표식 · 카탈로그 개정)은 `flushLocalDbResult` 로 sealed 를 실패로 본다.

### 3. 거부 뒤 규칙(재검토 B-2 (다))
- 봉인 알림을 받으면 공통으로: 동기 pause(풀지 않음) · Loki autosave 끔(500ms 재시도 고리 방지) · 휴식 소리 끔 · **presence 잠금 놓기**(M-5) · `bye` 알림.
- `writer_lost` 이거나 이미 주인을 잃은 탭 → 덮개 `tab-elsewhere`(data-state=elsewhere).
- 주인(또는 아직 모름)인데 `stale`/`versionchange` → **1회 새로고침**. 표식 `sessionStorage liftgram.tabs.staleReload`(시각) — 60초 안에 또 거부되면 새로고침하지 않고 중립 문구 덮개(data-state=external · 「저장소가 바깥에서 바뀌었어요」 · H-3 ②). 「여기서 계속하기」는 표식을 지우고 새로고침.
- 「아직 모름」을 주인 쪽으로 둔 이유: 셸 effect 전(steal 전)에 거부되는 새 탭, 또는 잠금·채널이 둘 다 없는 브라우저 — 새로고침 1회가 덮개보다 낫고 60초 표식이 고리를 막는다.

### 4. UX 넘겨주기
- `startTabGuard`: presence 요청 → `isImportRunningElsewhere()` → 가져오는 중이면 `setElsewhere("importing")`(이제 봉인도 함 · M-9) · 아니면 `claimWriter()` = `navigator.locks.request("liftgram-writer", {steal:true})` + 채널 `claim`. 주소창 미리 렌더 중이면 `prerenderingchange` 뒤(L-2).
- 빼앗긴 탭(steal → AbortError, 잠금 없는 브라우저는 채널 claim): 쓰기 문 닫기 → `writeQueueBarrier()`(최대 3초) → **바뀐 것이 있을 때만** 내려쓰기(`flushLocalDbIfDirty`) → 봉인 → 덮개. 새 탭은 기다리지 않는다.
  - 「바뀐 것만」인 이유: 명시 저장은 바뀐 게 없어도 loki versionId 를 새로 써서, 이미 디스크를 읽은 새 탭이 첫 저장에서 거부 → 매번 1회 새로고침이 생긴다. 진 탭에 미저장 변경이 있을 때만 그 비용을 낸다(그때 새 탭은 새로고침으로 그 변경을 받아 온다).
- 봉인 탭은 핑에 답하지 않는다(잠금 없는 브라우저의 탭 수에서 빠짐).
- `@app/core/db` 를 여는 모든 문서가 루트 layout → AuthProvider → `installSync` → `startTabGuard` 를 탄다(`/diag/db` 포함 · `/sw-nudge.html` 등 정적 파일은 layout 밖).

### 5. 리셋·혼자 쓰는 사용자(H-3)
- 계정 전환 리셋: `deleteDatabase` 가 `_prevLokiVersionId=null` · 새 어댑터도 null · 빈 DB load 는 prev 를 건드리지 않음 · 디스크 loki 청크 없음 = null → 첫 저장 fast path. 단위 테스트 2건(raw Loki · 실제 Watermelon `unsafeResetDatabase`) + e2e ④-2(실제로 `Database is now reset` 로그를 확인한 뒤 저장·새로고침, 봉인 로그 0).
- 새로고침 ×5(저장 직후)·업데이트 새로고침·`/diag/db` 왕복: e2e ④ — 봉인/거부 로그 0 · staleReload 표식 없음 · 덮개 0.
- bfcache 복귀: `pageshow.persisted` 면 새로고침(낡은 사본으로 거짓 덮개를 띄우지 않음 — e2e 없음, 아래 위험).
- 한 문서 Database 둘: `globalThis.__liftgramDb` 비교로 console.error(운영에서 throw 안 함).

### 6. 백필 표식(H-4)
- `MarkerStore.persist()`(웹 = `flushLocalDbResult() === "saved"`)가 false 면 표식 없이 멈춤(다음 부팅에 다시 · 멱등). 카탈로그 개정 표식도 saved/unreachable 일 때만.

### 7. 기존 동작 변경(의도)
- 두 번째 탭을 열면 첫 탭은 덮개가 된다(예전: 둘 다 쓰고 서로 덮어씀). 그래서 「다른 탭이 열려 있으면 가져오기 막힘」은 Web Locks 브라우저에서 닿지 않는다(봉인 탭은 presence 를 놓음 — 쓸 수 없으니 막을 이유도 없다). 기존 e2e 를 그렇게 고쳤다(원본은 `test.skip` 로 보존).

## 남은 위험

1. **배포 과도기 옛 번들 탭(M-2)** — 패치 없는 옛 탭이 열려 있으면 그 탭의 slow path 는 여전히 새 탭 기록을 지울 수 있다(안전망은 자기 저장만 지킨다). 새 탭이 거부되면 1회 새로고침으로 옛 탭의 디스크를 받아 오지만, 옛 탭이 그 뒤에 또 쓰면 새 탭 기록이 지워진다. `writerProto` 응답·「다른 탭을 새로고침해 주세요」 띠는 구현하지 않았다 — 릴리스 노트에 「배포 뒤 열린 탭은 새로고침」 안내 권장.
2. **bfcache 복귀 새로고침**은 e2e 없음(Chromium 은 Web Lock 을 쥔 문서를 bfcache 에 넣지 않는 것으로 알려져 실측 곤란). Safari 실기 확인 필요.
3. iOS Safari·삼성 인터넷 실기에서 `steal` 동작·덮개 확인 안 함(Safari 15.4+·Chromium 69+ 지원 범위 · 미지원이면 채널 경로 — ⑥ 이 그 경로를 덮음).
4. 넘겨주기 경합(진 탭이 새 탭 load 뒤 내려쓰기)이면 새 탭이 1회 새로고침한다 — 새 탭이 그 짧은 사이에 적은 것은 잃을 수 있다(진 탭에 미저장 변경이 있을 때만 생김).
5. sessionStorage 표식은 탭 복제 때 복사된다 — 복제 직후 60초 안에 거부되면 새로고침 대신 중립 덮개(무해).
6. 두 탭에서 같은 설정을 바꾸면 따라가던 기존 UX(qa1·muscle e2e)는 이제 진 탭이 덮개라 의미가 줄었다(기록 안전을 위한 의도된 변경).
7. **기존 경합(이번 범위 밖 · 발견만)**: 빈 DB 첫 실행에서 부팅 시드 top-up(`topUpSeedCatalog` — write 밖에서 조회 후 생성)과 `/exercises` 의 카탈로그 받기가 겹치면 `Duplicate key for property id: seed-walking` → Watermelon `DatabaseDriver is broken` → 종목 동기 「실패」. Web Locks 없는 모드(핑 250ms 지연)·부하 상태에서 한 번 재현(⑥ 이 무거운 ⑤ 뒤에 돌 때 2/8), 단독 반복(운영·수정 빌드 각 6회)에서는 재현 안 됨. ⑥ 은 첫 실행을 잠금 있는 채 끝내도록 바꿔 피했다. 별도 수정 후보(조회를 write 안으로).
8. Next dev HMR 이 `database.ts` 를 다시 평가하면 한 문서에 Loki 가 둘이 되어 거짓 봉인될 수 있다(개발 전용 · console.error 로 보임).
