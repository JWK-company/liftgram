## 속도 — 원인과 처치(코디네이터 실측 반영)
원인: 이 맥에서 운영 경로 왕복은 0.6~0.9초다(CF LAX 엣지 · `loc=KR colo=LAX` · 세션 갱신 TTFB 0.60/0.89/0.90초 실측). 탭을 옮길 때마다 아래 셋이 매번 일어났다.
- 문서를 새로 받았다(`<a href>`).
- JS를 다시 실행하고 로컬 DB를 다시 열었다.
- 세션 갱신과 Me를 차례로 다시 불렀다.

| 항목 | 전(v0.23.2 · 운영) | 후(v0.24.0 · 운영) |
|---|---|---|
| 탭 이동 | 문서 전체 새로 받기 · 비로그인 TTFB 314ms(SW 경유)·DCL 396ms · 요청 37개 · 로그인이면 갱신+Me 2왕복(≈1.2~1.8초) 추가 | 같은 문서 · 누름→화면 21~36ms · 새 요청 0개(미리받기) · 세션 왕복 0 |
| 앱 실행 세션 복원 | 갱신 → Me 직렬 2왕복 | 갱신 1왕복(라우트가 Me 동봉) + 직전 사용자 캐시로 첫 칠하기 |
| 로그인 깜빡임 | 확인 중 비로그인 화면·로그인 폼·피드백 탭 들쭉날쭉 | 캐시로 첫 칠하기 · 캐시 없으면 restoring 동안 폼 대신 로고 |
| 탭 셸(SW) | 네트워크 우선(최대 3초 대기) | 이 빌드의 셸을 곧바로 + 뒤에서 갱신(쿠키 읽는 signin·signup·account 제외) |
| 피드 첫 로드 | 세션 확인 끝난 뒤 시작 | 캐시 사용자면 곧바로 시작(갱신은 단일 비행 공유) |

⑤ 첫 로드 청크 분할은 이번에 하지 않았다. 탭 이동이 클라이언트 이동이 되면서 첫 로드 이후에는 다시 받지 않는다. 남은 첫 실행 비용은 P5에서 잰다.
