# Feature Spec — 운동 완료 시 루틴 반영·루틴으로 저장

> 생성일: 2026-10-27 · 등급: **Feature** (core 도메인·저장소 + 로컬 스키마 v24 + 프론트 시트 3곳 · 서버 변경 없음)
> 추적: SRS-059 · SRS-060 (URS-019 · UCS-022) · 피드백 #46 · #60 · #59(일부)
> 확정 결정(2026-10-27 사용자 「전부 A」): 아래 D1~D6

## 작업 의도
계획대로만 운동하지 않는다. 오늘 바꾼 것 중 **계속 할 것만** 루틴에 남기고, 바뀐 구성을 새 루틴으로 저장하거나, 오늘만으로 둘 수 있게 한다. 빠른 운동으로 즉석에서 짠 구성도 끝낼 때 루틴으로 저장한다.

## 확정 결정
| # | 결정 |
|---|------|
| D1 | 변경 = **종목 교체·추가·삭제·세트 수·순서·슈퍼셋 묶음/해제**. 무게·횟수·휴식·기록 칸 변형(그립·적재·브랜드·부착물)은 변경 아님(다음 시작 때 지난 조합·지난 기록이 뜬다) |
| D2 | 세트 수 = **완료 체크한 워킹 세트 수**(워밍업 제외). 덜 한 날은 「3 → 2」로 보이고 체크를 끄면 루틴 유지 |
| D3 | 운동 중 「이번만 / 루틴에도」 질문 **제거** — 완료 때 한 번에 고른다(코드 보존 규칙: 호출만 막음) |
| D4 | 루틴으로 저장 = 완료 세트가 있는 종목 · 순서 · 슈퍼셋 · 완료 세트 수 · 횟수 범위(루틴 값, 없으면 그날 워킹 세트 횟수 min~max) · 휴식(원래 값/기본). **무게·변형 미저장**. 기본 이름 「원래 이름 (수정)」 / 「M/D 주 근육 2개」, 중복이면 「(2)」 |
| D5 | 세트별 처방(prescription)이 있는 루틴은 「바꾸기」 비활성(이유 표시) → 새 저장·오늘만 |
| D6 | 요약 화면·기록 상세에 「이 운동으로 루틴 만들기」(#59 일부) |

## 설계
### 짝짓기(교체 판정의 기반)
- 로컬 스키마 **v24**: `workout_exercises.routine_exercise_id`(optional, 동기 대상 — 서버는 컬렉션 이름만 검증하므로 서버 변경 없음). `startWorkoutFromRoutine` 이 채운다. 운동 중 종목 교체(`swapWorkoutExercise`)는 같은 행을 고치므로 연결이 유지된다 → 「교체」.
- 연결이 없는 옛 운동·추가 블록: 같은 `exercise_id` 의 남은 루틴 줄과 순서대로 짝, 남으면 추가/삭제.
- 같은 종목이 루틴에 두 번 있어도 연결 id 로 구분된다.

### 도메인 `core/domain/routineDiff.ts`(순수)
- 입력: 루틴 줄(`id·exerciseId·targetSets·sortOrder·supersetGroup·prescription`), 운동 블록(`id·exerciseId·routineExerciseId·sortOrder·supersetGroup·doneWorkingSets`).
- 출력: `RoutineChange[]` — `swap{reId, from, to}` · `add{weId, exerciseId, at}` · `remove{reId}` · `sets{reId, from, to}` · `order{before[], after[]}`(한 항목) · `superset{groups before/after}`(한 항목). 완료 세트 0 인 블록은 「하지 않은 종목」 → 루틴 줄 기준으로 `remove` 후보(기본 **체크 해제** — 그날 건너뛴 것일 가능성이 커서).
  - 주의: 블록이 완료 세트 0 이면 sets 변경으로 보지 않는다(remove 후보로만).
- `hasPrescription` 이면 `canApply=false`.
- `applyRoutineChanges(routineId, workoutId, selected)`(저장소): 한 번의 `database.write` 로 선택 항목만 적용. 추가 줄은 그 블록의 목표 횟수·휴식을 복사, 변형 칸은 비움(지난 조합 승계 규칙). 순서·슈퍼셋은 선택 시에만 오늘 배치로.
- `saveWorkoutAsRoutine(workoutId, name)`(저장소): D4.
- 기본 이름 `suggestRoutineName(workout, muscles)`.

### 화면
- `ActiveWorkout` 완료 확인 → `completeWorkout` → (루틴 운동 & 변경 있음) **변경 시트** / (빠른 운동 & 완료 세트 ≥1) **저장 질문 시트** → 요약. 시트 닫기 = 오늘만/저장 안 함.
  - 변경 시트: 세 버튼 → 「바꾸기」는 항목 체크 목록(교체·세트 수·추가 기본 체크, 「하지 않은 종목 빼기」 기본 해제) + 「반영」.
  - 새 저장: 이름 입력(기본값) → 저장 → 토스트 「루틴 ○○ 저장」.
- `WorkoutSummary`·기록 상세(`history/[id]`)에 「이 운동으로 루틴 만들기」.
- 운동 중 「이번만 / 루틴에도」 호출 주석 처리(D3).
- 문구 한/영.

### 테스트
- 단위 `routineDiff.test.ts`: 예시(벤치 교체 + 플라이 2→3, 벤치는 미선택 반영 → 루틴 벤치 그대로·플라이 3) · 변형만 변경 = 변경 없음 · 추가·삭제·순서·슈퍼셋 · 같은 종목 2줄 · 연결 없는 옛 운동 · 워밍업 제외 · 처방 루틴 canApply=false · 완료 0 블록.
- 저장소 테스트: apply 원자성·선택만 반영 · saveWorkoutAsRoutine 내용(D4) · 이름 중복.
- e2e: 루틴 운동 교체+세트 추가 → 완료 → 선택 반영 → 루틴 다시 시작 시 반영 확인 · 오늘만 → 루틴 불변 · 빠른 운동 → 저장 → 루틴으로 시작 · 요약에서 루틴 만들기 · 변형만 바꾼 운동 → 시트 없음.
