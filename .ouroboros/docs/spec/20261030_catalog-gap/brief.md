# 오픈짐 ↔ 리프트그램 종목 대조 — 공통 지시

모든 출력(파일 내용·이유 문구)은 **한국어**로 쓴다(영문 이름 칸만 영어).

## 목표
리프트그램 카탈로그(480행)에 **없는 동작**만 골라 새 종목 후보로 만든다. 오픈짐(영문 운동 영상 데이터셋)은 같은 운동을
그립·손잡이·버전·한 팔/두 팔·촬영 시점마다 따로 세서 중복이 많다. 그것들은 「이미 있음」으로 접어야 한다.

## 입력 (모두 이 폴더: /private/tmp/claude-501/-Users-woobi-Desktop-tarae-liftgram/cc0fac10-a48f-447f-9b27-a359273dcc6f/scratchpad/og/)
- `chunks/<묶음>.tsv` — 판단할 오픈짐 종목. 열: 오픈짐id · 영문이름 · 기계번역 한국어 · 기구 · 대상근육 · 유형
- `ours-brief.tsv` — 우리 카탈로그. 열: seed id · 영문 · 한국어 이름 · 기구 · 주동근 · family(동작 그룹) · 한국어 별칭(;) · 영문 별칭(;)
- `families.txt` — 기존 family 목록

## 우리 종목 모델 (반드시 지킬 것)
같은 종목으로 본다(= 「있음」, 새로 만들지 않음):
- 그립 폭·방향(와이드·클로즈·언더·뉴트럴·리버스), 케이블 손잡이(로프·V바·스트레이트 바·싱글 핸들), 머신 브랜드·핀/플레이트 적재 — 우리는 이걸 「변형 칸」으로 고른다
- 한 팔/두 팔/교대 — 우리는 세트 속성
- 「v. 2」「(male)」「(side pov)」 같은 영상 버전, 「full range of motion」 같은 수행 디테일
- 무릎 꿇기/반 무릎 같은 사소한 자세 차이 — 우리에 가장 가까운 종목이 있으면 그것으로

다른 종목으로 본다(= 새로 만들 수 있음):
- 기구가 다르면 다른 종목: 바벨·덤벨·케이블·머신·스미스·케틀벨·밴드·맨몸·EZ바·트랩바는 각각 별도 (예: 「덤벨 업라이트 로우」와 「바벨 업라이트 로우」는 별개)
- 벤치 각도(플랫·인클라인·디클라인), 자세가 자극 부위나 셋업을 실제로 바꾸는 경우(라잉/시티드 레그 컬, 스탠딩/시티드 카프 레이즈, 프리처 컬 등)
- 동작 자체가 다른 것

## 할 일
묶음 파일의 모든 줄을 하나씩 판단해 셋 중 하나로 분류한다:
1. **matched** — 우리 종목 중 하나와 같은 종목(위 규칙). seed id 를 적는다.
2. **new** — 우리에게 없는 동작. 같은 새 동작에 해당하는 오픈짐 줄들은 **하나로 묶는다**(그립·버전 차이 등).
3. **excluded** — 넣지 않을 것: 스트레칭·재활·요가성 동작, 스포츠 드릴, 두세 동작을 이어 붙인 기묘한 조합(「밴드 플랭크 + 원암 풀다운」), 서스펜션/안정볼/메디신볼처럼 한국 헬스장에서 드문 도구 위주의 변형, 지나치게 특이한 것.

new 에는 등급을 붙인다:
- **A** 한국 헬스장에서 흔히 한다(PT·유튜브에서 자주 보이는 이름)
- **B** 알려져 있지만 덜 흔하다
- **C** 드물다(웬만하면 excluded 로 보내되, 애매하면 C)

## new 항목 작성 규칙
- `name_ko`: 한국 헬스장에서 실제 부르는 이름. 「기구 + 동작」(예: 덤벨 인클라인 로우, 케이블 크로스오버 로우). 맨몸은 동작만. 우리 기존 이름 표기 습관을 따른다(벤치프레스 붙여쓰기, 푸시업, 풀업, 레이즈 등 — ours-brief 참고). **기존 이름·별칭과 겹치면 안 된다.**
- `name_en`: 새 영문 이름(고유, 기존 영문·별칭과 겹치지 않게). 예: "Dumbbell Incline Row"
- `equipment`: barbell|dumbbell|machine|cable|bodyweight|kettlebell|band|smith|ezbar|trapbar|other
- `primary`: chest|back|shoulders|biceps|triceps|forearms|quads|hamstrings|glutes|calves|abs|traps|fullBody (하나) · `secondary`: 같은 값 배열(0~3개)
- `load_mode`: weight(외부 무게) | bodyweight(맨몸, 가중 가능) | assisted(보조 머신)
- `family`: 같은 동작 그룹이 기존 families.txt 에 있으면 그것을(예: 덤벨 업라이트 로우 → upright_row). 없으면 새 snake_case 이름을 만들고 `family_is_new: true`.
- `aliases_ko`, `aliases_en`: 사람들이 검색할 다른 이름(오픈짐 원래 영문 이름 포함 가능). 기존 종목의 별칭과 겹치지 않게.
- `similar`: 비슷한 운동으로 이어 줄 기존 family 1~4개
- `og`: 묶은 오픈짐 id 배열
- `why`: 왜 없는 동작인지 한 줄(우리 가장 가까운 종목과의 차이)

## 출력
`out/<묶음>.json` 하나에 아래 형태로 **파일로 저장**한다(유효한 JSON):
```json
{
  "chunk": "<묶음>",
  "total": 0,
  "matched": [{"og": ["id", "..."], "seed": "seed-..."}],
  "new": [{"og": ["id"], "name_ko": "", "name_en": "", "equipment": "", "primary": "", "secondary": [], "load_mode": "weight", "family": "", "family_is_new": false, "aliases_ko": [], "aliases_en": [], "similar": [], "tier": "A", "why": ""}],
  "excluded": [{"og": ["id", "..."], "reason": "짧게"}]
}
```
- 묶음 파일의 **모든 오픈짐 id 가 세 칸 중 정확히 한 곳**에 들어가야 한다(total = 줄 수). 저장 뒤 스크립트로 개수를 맞춰 확인하라.
- 다른 묶음(부위)에 있을 법한 동작이라도 이 묶음에 나온 것은 이 묶음에서 판단한다.
- 마지막 답장은 짧게: matched/new(A·B·C)/excluded 개수와 파일 경로만.
