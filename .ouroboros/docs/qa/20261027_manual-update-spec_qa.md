# /qa spec — 앱 업데이트 프로필 버튼 하나로 (SRS-085)

> 대상: `.ouroboros/docs/spec/20261027_manual-update/spec.md` · 2026-10-27 · 등급 Feature
> 참여 전문가(역할 = 이름):
> - **PWA·서비스워커 전문가** — 워커 수명주기(installing→installed→activating→activated→redundant)·clients.claim·controllerchange·캐시 세대
> - **모바일 UX 리뷰어** — iOS/Android 홈 화면 앱 · 덮개·실패 화면·탭 점 · 화면 정리 규칙
> - **신뢰성 엔지니어** — 데이터 유실·무한 대기·재시도 루프·전환기·오설정

## 판정: **조건부 통과** — 아래 H 2건·M 4건을 스펙에 반영한 뒤 실행

## High

| # | 관점 | 지적 | 반영 |
|---|------|------|------|
| H-1 | 신뢰성 | 필수 업데이트 **오설정 루프**: `MIN_CLIENT_VERSION` 이 실제 배포 버전보다 높으면, 업데이트해도 여전히 「최소 미만」 → 화면이 다시 보일 때마다 덮개 15초 → 실패가 반복된다(앱을 사실상 못 씀). | 필수 판정을 **`현재 < 최소` 이고 서버 `version` ≥ 최소(서버가 그 버전을 실제로 갖고 있음)** 일 때만으로 좁힌다. 서버 version 을 모르면 필수 아님(fail-open). `mandatoryUpdateAction` 입력에 `serverVersion` 추가 · 단위 테스트 추가 |
| H-2 | PWA | 기다리던 워커가 **redundant** 가 되는 경우(더 새 배포가 또 설치되어 대체 · 설치 중 실패): 저장소에 죽은 워커가 남아 버튼은 보이는데 skip-waiting 이 아무 일도 안 해 15초 실패만 반복. | `waiting` 워커의 `statechange` 를 지켜 `redundant` 면 비우고 `reg.waiting` 으로 다시 읽는다 · `updatefound` 는 매번 새 installing 을 추적(지금도 그렇다) · `startUpdate` 는 누른 순간 `reg.waiting` 을 **다시 읽어** 쓴다(저장소 값은 표시용) |

## Medium

| # | 관점 | 지적 | 반영 |
|---|------|------|------|
| M-1 | 신뢰성 | 15초 타이머·controllerchange·`statechange=activated` 대체 경로가 겹치면 **두 번 새로고침** 또는 새로고침 뒤 늦은 실패 표시 가능 | 새로고침은 한 곳(`reloadOnce`)으로 · 부르면 타이머 해제 · 실패 전이는 `phase==="updating"` 일 때만 |
| M-2 | 신뢰성 | 실패 후 「닫기」 했는데 늦게 워커가 활성화되면 `applying` 이 남아 있어 **사용 중 새로고침**이 생긴다(확정 3 위반) | 실패·닫기 전이 때 `applying=false`. 그 뒤의 controllerchange 는 `mark`(새로고침 없음 · 「업데이트」=새로고침만) |
| M-3 | 모바일 UX | 덮개 중 Android 뒤로 가기·iOS 가장자리 스와이프는 `inert` 로 막히지 않아 화면 이동이 덮개 뒤에서 일어난다 | 기능상 무해(곧 새로고침 · 기록은 이미 내려씀) — **보류**, 보고서 남은 위험에 적는다 |
| M-4 | PWA | 이번 배포의 waiting 워커는 **옛 템플릿이 아니다**(새로 새긴 버전 응답 있음). 그러나 전환기에 옛 문서(v0.45.0)가 새 워커(v0.46.0)를 기다리는 동안엔 옛 코드가 돈다 → 새 기능 없음. 스펙 R1 은 맞지만 **옛 번들의 자동 적용이 이번 배포를 적용**한다는 점까지 명시 필요 | 스펙 R1 에 「v0.45.0 기기: 홈 등 운동 화면 밖에서 자동 적용(옛 규칙) → 그 뒤 새 방식」 명시 · 보고서 사용자 알림점 |

## Low

| # | 관점 | 지적 | 반영 |
|---|------|------|------|
| L-1 | 모바일 UX | 프로필 「업데이트」가 회색 상자면 눈에 덜 띈다 | 의도(조용한 화면) — 탭 점이 알린다. 유지 |
| L-2 | 신뢰성 | 느린 망에서 필수 경로의 첫 설치(정적 파일 미리 받기 수 MB)가 15초를 넘길 수 있다 | 실패 화면 → 다시 시도(설치는 뒤에서 계속되므로 두 번째는 대개 성공) · 남은 위험에 기록 |
| L-3 | PWA | 오래 열어 둔 홈 화면 앱은 화면 이동이 클라이언트 이동이라 sw.js 를 다시 확인하지 않는다 → 새 버전을 오래 모름 | 화면이 다시 보일 때 `reg.update()`(10분에 한 번까지) — 받기만 하고 적용하지 않는다 |
| L-4 | 모바일 UX | 부팅 덮개 문구가 서버 렌더 고정 한국어 | `lang` 이 지금 "ko" 고정(i18n 기존 한계) — 같은 `tw` 로 그리므로 언어 설정이 붙으면 따라간다 |
| L-5 | 신뢰성 | 「운동 중」 확인이 기기 DB 를 못 열면(예외) | 막는 쪽(fail-closed): DB 확인 실패면 업데이트하지 않고 실패 화면 「다시 시도」 — 기록 보호가 우선 |

## 확인한 것(문제 없음)

- 앱을 완전히 닫았다 열 때: 기다리던 워커는 새 navigation 전에 활성화 → 새 문서가 처음부터 새 controller → controllerchange 없음 → 새로고침 없음(확정 3 · 테스트 E3 의 「표식 없는 부팅」으로 간접 확인).
- 첫 설치(controller 없음)의 claim → `ignore` 유지(0b3e8df 의 「첫 방문 화면 이동 끊김」 회귀 방지).
- `/app-version` 은 SW 가 가로채지 않고, 오프라인이면 판정 생략(필수 아님).
- 화면 정리 규칙: 빨강 채움은 실패 화면 「다시 시도」 하나 · 탭 점 ink3 · 새 토큰 없음.
