## 높음

### H-1 같은 종목·다른 조합 두 블록에서 PR이 사라지거나 엉뚱한 줄에 붙는다
- 파일: `src/frontend/app/components/session/WorkoutSummary.tsx:68-69, 138-140`
- 원인: `completeWorkout`은 PR을 **(종목 × 조합) 버킷마다** 따로 만든다(`workoutRepository.ts:2214-2241`, `performedByVariant` 키 `${exerciseId}::${variantKey}`). 그래서 `summary.prs`에는 같은 `exerciseId`가 두 번 들어갈 수 있다. 그런데 요약은 이것을 `new Map(summary.prs.map(d => [d.exerciseId, d]))`로 **종목 id 하나에 묶는다**. 그 결과 뒤 항목이 앞 항목을 덮는다. 이어서 `prShown`이 「그 종목의 첫 줄에만」 단다.
- 재현
  1. 빠른 운동에 「랫풀다운」 블록 A(기구 브랜드 X)와 블록 B(브랜드 Y)를 둔다. 둘 다 그 조합의 첫 기록이라 PR 2개씩 선다.
  2. 완료하면 머리는 「PR 갱신 4회」다. 그런데 종목 줄에는 블록 A 줄에만 「PR 2」가 붙는다. 이 2는 B의 것이다. B 줄에는 아무것도 없다.
  3. 버킷마다 PR 수가 다르면(A는 1개, B는 2개) 숫자 자체가 틀린다.
- 영향: D5의 전제(「PR n」 합 = 머리 PR 수)가 깨진다. 무엇을 깼는지 화면에 남는 유일한 단서가 틀린 줄을 가리킨다. 변형 버킷 불변식(PR 버킷 = 종목 × 기구)을 화면 계층에서 어긴다.
- 수정안
  1. `WorkoutPRDetail`에 `variantKey`(또는 `workoutExerciseId` 목록)를 실어 보낸다.
  2. `BreakdownRow`에도 `variantKey`를 싣는다.
  3. 요약은 `${exerciseId}::${variantKey ?? ""}`로 묶는다. 같은 버킷이 두 블록(슈퍼셋·중복)이면 첫 줄에 한 번만 단다. 이 부분은 지금 로직을 유지한다.
  4. e2e에 「같은 종목·다른 브랜드 두 블록」 시나리오를 추가한다. 단언은 「PR n」 합 = `summary-prs`.

## 중간

### M-1 공유 시트를 요청 중에 닫았다 다시 열면 두 번 올릴 수 있다
- 파일: `WorkoutSummary.tsx:236-258`, `ShareWorkout.tsx:146-185`
- 원인: 「올리는 중」(`sharing`)은 시트 안 `ShareWorkout`의 지역 상태다. 요약이 들고 있는 것은 `shared`(완료)뿐이다. 그런데 시트는 바깥을 누르거나 닫기 버튼으로 요청 중에도 닫힌다. 닫혔다 열리면 새 인스턴스는 `sharing=false`로 시작한다.
- 재현: 느린 네트워크에서 「피드에 공유」를 누른다 → 곧바로 시트 바깥을 누른다 → 요약의 「공유」를 다시 누른다 → 다시 「피드에 공유」를 누른다. 첫 요청이 끝나기 전에 두 번째 `createPost`가 나간다. 피드에 같은 카드가 두 장 생기는데, 코드 주석이 막으려던 바로 그 상황이다.
- 수정안: 「올리는 중」도 요약으로 올린다. 방법은 둘 중 하나다.
  - `onSharingChange`를 두고, 요약의 버튼을 `disabled={!extras || shared || inFlight}`로 막는다.
  - 요청 중에는 시트 닫기를 막는다.

### M-2 한 줄·한 카드 안에서 단위가 섞이고, 같은 1RM이 화면마다 다르게 보인다
- 파일: `WorkoutSummary.tsx:150, 156` · `WorkoutDetailClient.tsx:336, 352` · `StatsClient.tsx`(1RM은 `weightUnit`)
- 관찰(캡처 `after/summary-360x640.png`, `after/stats-390-dark.png`)
  - 요약 한 줄에 「2세트 · 볼륨 338kg · 1RM 48lb」가 함께 보인다.
  - 기록 상세 카드는 세트 「30lb × 12」, 1RM 「48lb」, 볼륨 「338kg」이다.
  - 같은 날 분석은 「덤벨 플라이 21.5kg」이다.
- 영향: F5 범위(분석은 kg 유지)대로 구현은 맞다. 그러나 사용자 눈에는 「요약 48 ↔ 분석 21.5」가 같은 값으로 읽히지 않는다. 한 줄 안의 kg·lb 혼재는 오기처럼 보인다.
- 수정안(작은 것부터)
  1. lb 블록이면 볼륨 조각에 단위를 밝히거나 「볼륨(kg)」으로 적는다.
  2. lb 1RM 옆에 괄호로 kg 환산(「48lb ≈ 21.5kg」)을 단다. 요약과 상세에만 단다.
  3. P4에서 분석·종목 상세 단위 정책을 다시 정할 후보로 기록한다.

### M-5 360폭·긴 값이면 1RM이 말줄임 뒤로 사라진다 (의심 — 실측 안 함)
- 파일: `WorkoutSummary.tsx:144-159` + `ui/rows.tsx` ListRow subtitle(`truncate`)
- 원인: 1RM을 subtitle **맨 끝 조각**에 붙였다. subtitle은 한 줄 `truncate`다. 오른쪽에는 「PR n」 value가 `shrink-0`으로 자리를 먼저 잡는다.
- 재현(추정): 360폭, 「5세트 · 볼륨 12450kg · 1RM 133.5kg」 + 「PR 2」. 텍스트 영역은 약 240px이고, 문자열은 약 230~250px이다. 경계에서 「1RM 13…」이나 「…」로 잘린다. en 로케일 「5 sets · Volume 12450kg · 1RM 295lb」는 더 길다. 캡처 시드는 네 자리 볼륨뿐이라 이 경우가 드러나지 않았다. 다섯 자리 볼륨이 넘친다는 이유로 KPI를 3칸으로 줄였다는 주석과도 같은 문제다.
- 수정안: 이 줄만 `truncate` 대신 줄바꿈(`whitespace-normal`)을 허용한다. 아니면 1RM을 value 쪽(「PR n」 아래 회색 작은 글자)으로 옮긴다. 360 × 다섯 자리 볼륨 × en 시드로 `scrollWidth <= clientWidth` 좌표 검사를 추가한다.

## 중점 점검 항목별 결론

1. **정보 손실·회귀**
   - KPI 3칸 + 금색 PR 수 한 줄 구성에서 숫자 자체(볼륨·시간·세트·PR 수)는 빠지지 않았다. KPI 3칸은 원래도 3칸이었고 `summary-prs`는 숨김 span으로 유지된다.
   - 빠진 것은 PR 값과 이전 값(M-3)이다. 버킷 충돌로 PR 수도 틀릴 수 있다(H-1).
   - 분석 「최근 PR」은 상위 1RM 목록에 모두 나왔을 때만 숨긴다. 기록이 없을 때는 빈 안내를 낸다. 이 조건은 맞다. 종목당 1줄 축소로 갱신 이력은 화면에서 사라진다(L-5).
   - 공유: 완료 잠금은 동작한다. 다만 요청 중 재진입(M-1)과 한마디 유실(L-1)이 있다.
   - 「요약을 다시 열면 초기화」: 요약은 완료 직후 한 번만 마운트되고 다시 시작 시 언마운트된다. 재열기 경로가 없어 실해는 없다. 새로고침 후에는 요약 자체가 없다.
   - 「실패」 색은 M-4.
2. **단위**
   - lb 1RM 계산은 정확하다. kg 정본을 `formatWeight(…, "lb")`로 1lb 반올림하며, 추정값이라 적절하다.
   - 블록 단위는 블록 하나에 하나라서 한 블록 안 kg·lb 혼재는 없다. 같은 종목 두 블록(kg·lb)은 줄마다 제 단위로 보인다. 다만 그때 PR이 붙는 줄이 틀린다(H-1).
   - 화면 간 혼란은 M-2.
3. **레이아웃**
   - 360폭 KPI는 넘치지 않는다(캡처 확인). 종목 줄 subtitle 말줄임은 M-5(의심).
   - 대비: QuietAction 완료 상태 L-6, 실패 색 M-4. 금색 caption(#A16207 / surface)은 약 4.6:1로 경계 통과.
   - 탭 목표: QuietAction 56px, 상세 세트 줄은 기존 버튼이다. 통과.
   - 총평과 완료 버튼 겹침은 캡처상 full-page 아티팩트다. 실제는 미확인(L-7).
4. **테스트**
   - 측정 e2e의 요약·상세 단언은 옛 코드에서 실제로 실패하고 회귀를 막는다.
   - 분석 겹침 단언은 공허하다(M-7). `workout.spec` PR 단언도 약해졌다(M-6).
   - `history-replay`·`profile-edit`: 「btn-share-workout 비활성」을 「btn-summary-share 비활성」으로 바꿨다. 같은 `shared` 상태에서 파생되므로 검증 범위는 사실상 유지된다. 다만 「올린 뒤 시트가 닫힌다」(`share-sheet` count 0)는 단언하지 않는다.
   - `history-replay:112`의 `detail-set-oneside`는 이제 머리 표시를 잡는다. 「×2」 단언은 유지되지만, 세트 무게(「한쪽 40kg」) 검증은 사라졌다.

## 권장 처리 순서
H-1 → M-1 → M-6·M-7(테스트 보강) → M-4·M-5 → M-3·M-2(사용자 판단 필요 — 결정 D5·F5 범위 조정) → 낮음은 P4에서 묶어 처리.
