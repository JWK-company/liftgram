## 위험별 점검 메모(이상 없음 확인)
- 계산 무게 경로: 볼륨·PR(`personalRecords`)·1RM(`oneRepMax`·analytics)·요약·공유(`sharePayload`)·기간 성과(`periodSummary`)·피드(`WorkoutBox`)·라이브 PR(`evalLiveSetPr`)·서버 코칭은 모두 `effectiveMultiplier`/`load_multiplier`(null=1)를 곱한다. 근육 집계는 세트 수 기반이다. 배수를 빼먹은 경로는 없다.
- 질문 답 retag: 같은 운동의 그 종목 블록 전부, 한 세트 포함, 숫자 그대로 → 요구와 맞다. `database.write` 안에서 다시 읽어 직렬화된다. `addSet`은 블록 마지막 세트의 배수를 따라 블록 안 배수가 같게 유지된다.
- 키 불변식: 배수는 세트 속성이고 `variant_key`를 바꾸지 않는다. 빈 적재 칸은 키 그대로이고 `load_default`는 배수 결정에만 쓰인다.
- 카탈로그 재적재: 종목 행 필드가 바뀌지 않아 `refreshSeedCatalog`는 0건으로 멱등이다. 사용자 행(선호·커스텀)은 건드리지 않는다. 생성 스크립트가 `load_default` 누락·오값에서 실패한다.
- 서비스워커: 경로 판정이 쿼리·하위 경로를 처리하고 `/workouts`는 제외한다. `/workout`에 운동·요약이 없으면 `leaveSession`이 홈으로 보내므로 영원히 보류되지 않는다. 앱을 닫으면 다음 실행에서 브라우저가 새 워커를 활성화한다. 자동 적용 직전 기기 DB 진행 중 확인과 flush는 유지된다. 완료 시트 저장은 flush한 뒤 `onDone`한다.
- #62: 첫 ⌃·끝 ⌄은 흐린 비활성, 블록이 하나면 숨김, 슈퍼셋 멤버에는 없음. 유산소 블록도 도구 줄(휴식·메모·순서)은 있고 질문은 없다. 390px 가로 넘침 없음. 다크 토큰 정상. 빨강 0(e2e 전 채널 가드).
