## 핵심 의견

1. **흐름·상태·계정 분리는 잘 됐다.** 진입 → `/stats/summary` → 보내기 시트로 2화면 + 시트 1이다(U-15). 「보는 그대로 보낸다」(omitSections → parseSummaryV1 결과가 미리보기이자 스냅샷)가 코드 한 줄로 지켜진다. 대기열은 키를 계정별로 나누고, 주인을 대조하고, 로그아웃·전환 때 지우고, 영구 실패를 분류한다(U-16). 이 부분은 e2e가 서버 저장값까지 확인한다. DM 카드에는 숫자가 없고 받는 쪽에만 「루틴 처방」이 있다. 열 때 상태 5종(로딩 스켈레톤·오프라인·해지·없음·읽기 실패)도 갖췄다(U-17). i18n은 ko·en 104키로 짝이 맞고 `summary.` 접두사와 겹치지 않는다. 웰니스 게이트(PREFIXES `progressSummary.`)를 통과하며, 평가·권고 문구는 없다. 빨강은 「선택 칩 테두리 + 보내기 채움」 2종이고 오류 글자는 의미 색이라 공용 규칙 안이다.
2. **숫자 정확성에 구멍이 하나 크게 있다.** 맨몸·보조 종목의 「유효무게」에는 체중이 들어간다. 그래서 체중 섹션을 꺼도 「많이 한 종목」·「새 기록」 숫자로 코치에게 체중이 그대로 간다(S-11 약속 위반). 같은 세트가 트레이너 리포트에서는 가중분만으로 보여서, 코치는 한 세트를 두 숫자로 보게 된다(P4U-1). 체중 표시 단위도 SRS-067(kg 고정)과 어긋난다(P4U-2).
3. **같은 기기 통계 화면과는 숫자가 다르게 나오는 게 정상인데, 화면은 그걸 말하지 않는다.** 두 화면은 기간 경계(달력 자정 기준인지, 지금부터 7×24시간인지)·운동 시각 기준(started_at인지 completed_at인지)·볼륨 정의(캐시 합인지, 세트를 다시 계산한 합인지)·세션 정의가 모두 다르다(P4U-4). 「새 기록 n개」와 목록 줄 수도 서로 다른 출처에서 와서 어긋날 수 있다(P4U-3).
4. **오프라인 판단:** `/stats/summary`는 오프라인 셸에 **넣어야 한다.** 계산은 전부 기기에서 하고 대기열도 이미 있다. 그런데 처음 여는 순간이 오프라인이면 /offline으로 막혀서 대기열 기능의 첫 진입이 죽는다. 다만 셸만 넣으면 「코치 캐시 없음 + 오프라인」일 때 「코칭 중인 코치가 없어요」라는 **거짓 빈 상태**가 보인다(P4U-5). 그래서 이 둘은 함께 고쳐야 한다.
