## 핵심 의견

1. 칩·시트 구조는 스펙대로 잘 만들었다. 저장은 블록 쓰기 직렬화를 타고, 끄면 DOM 이 0개이며, 좌표 기준선 검사와 포커스 복귀도 있다. 처방 줄 합치기 4가지 경우(목표만·실제만·둘 다·없음)와 설정 즉시 반영(PREFS_EVENT + useSyncExternalStore)은 코드상 맞다. 휴식 타이머와 완료 흐름에도 영향이 없다. 완료 쓰기를 await 한 뒤에 휴식이 시작되고, RIR 저장은 `user_edited` 를 건드리지 않는다. 슈퍼셋 줄도 같은 `SetRowEdit` 를 써서 똑같이 동작한다.
2. 고칠 곳은 대부분 **분석 쪽 표시**에 모여 있다.
   - 분석 화면에서 Epley 주석이 노력 카드 밑에 붙는다(CU-1).
   - 다크 모드에서 진척 막대 채움이 카드 바탕에 묻혀 1RM 막대가 짧아 보인다(CU-2).
   - 분포 칸 이름이 실제 값과 어긋난다(3.5 → 「여유 4개 이상」 · CU-3).
   - 빈 상태 문구가 「기간 안에 없음」과 「한 번도 없음」을 가르지 않는다(CU-4).
3. 접근성에서는 칩의 aria-label 이 보이는 글자(「목표 2」)를 덮어 label-in-name 을 어긴다(CU-5). SchemaGuard 는 포커스를 옮기지 않고 뒤 화면을 막지도 않는다(CU-6).
4. 낙관 표시는 일반적인 흐름에서는 안전하다. 다만 **같은 세트에 앞선 쓰기가 아직 대기열에 있을 때** 저장값을 기다리지 않고 풀린다. 그러면 옛 값이 잠깐 보이고, 그 사이 시트를 다시 열면 스테퍼가 옛 값에서 시작한다(CU-7). 드물어서 중간 아래로 매긴다.
5. e2e 는 실패를 잡는 단언이 대체로 좋다(포커스 testid, 좌표 차이, IDB 요약 동일성). 다만 경합·rpe 환산·분포 칸·화면 그대로 설정 반영·가드 버튼은 검사하지 않는다(CU-12).
6. i18n 은 빠진 키가 없다(ko·en 49키 대칭). `summary.` 접두사도 쓰지 않아 다른 세션과 충돌하지 않는다. 웰니스 위반(권고·평가)도 없다. 하드코딩된 aria 두 개(「감소」·「증가」)만 en 이 없다(CU-9).
