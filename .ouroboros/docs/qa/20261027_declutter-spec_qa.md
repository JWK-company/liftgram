## 결과 — 조건부 통과 (높음 3 · 중간 5 · 낮음 3)

### 높음
- **Q1. 조용한 칩 글자 대비 부족** (접근성) — `--p-ink3` #6A737B 를 `--color-surface-alt` #F1F2F4 위에 쓰면 4.31:1 로 4.5 미만이다. 같은 글자도 흰 바탕에서는 4.83:1 로 기준을 넘는다. 금색 #A16207 은 흰 바탕에서 4.92:1, 다크 #FFD23F 는 #2B2B2B 위에서 9.81:1 이다. → `QuietChip` 글자는 `--color-ink2` 로 고정한다. `MetaLine` 은 카드(흰) 바탕에서만 ink3 를 허용한다. P1 수용 기준에 대비 검사(계산 스타일)를 넣는다.
- **Q2. 피드 「자동 문구」는 표시 문제가 아니라 저장된 본문이다** (e2e·데이터) — `session/ShareWorkout.tsx:131,152` 의 `autoCaption()` 이 「운동 완료! …」를 **게시물 본문으로 저장**한다. 그래서 표시할 때 자동 문구인지 사람이 쓴 글인지 구별할 수 없다. → D7 의 「자동 문구 제거」는 **앞으로 공유할 때 자동 본문을 만들지 않는 것**(빈 한마디면 본문 없음, 서버가 빈 본문을 허용하는지 확인)으로 정의한다. 기존 게시물 본문은 그대로 둔다. 카드의 숫자 한 줄이 그 정보를 대신한다.
- **Q3. 접기 안으로 들어가는 요소의 e2e 누락** (e2e) — 스펙 표에 `tip-toggle`(`e2e/pictogram.spec.ts:41`)이 빠졌다. 운동 방법이 `Fold` 안으로 들어가면 실패한다. → e2e 표에 추가하고, 공용 헬퍼 `블록_더보기(page, n)` 를 `e2e/helpers` 에 두고 모든 호출부가 이 헬퍼를 쓰게 한다.

### 중간
- **Q4. F4 원인 미확정** — `RestBar` 는 `main` 안의 sticky `z-40` 이고, 시트는 `#modal-root`(main 밖, `layout.tsx:102`)의 fixed `z-50` 이다. 숫자만 보면 시트가 위여야 하는데, 보고서는 휴식 막대가 위로 뜬다고 관찰했다. → 구현 전에 쌓임 맥락을 확인하는 e2e(시트를 연 뒤 RestBar 중심점의 `elementFromPoint` 가 스크림인지)를 먼저 쓰고, 실패를 재현한 다음 고친다. 재현되지 않으면 「재현 안 됨」으로 닫는다.
- **Q5. 홈 진행 중 카드 제거 후 홈에서 막대가 보이는지** — `GlobalWorkoutBar.tsx:100` 은 `/workout` 밖에서 보이므로 홈에서도 보인다. 다만 이번 주 요약·빠른 시작과 막대가 겹치지 않는지 좌표로 확인해야 한다. `btn-discard-active`(카드 ⋯ 안 폐기)의 기능은 막대의 `global-workout-cancel` 이 대신한다. → e2e 표에 `routines.spec.ts` 의 resume 시나리오를 `global-workout-bar` 로 바꾸는 것을 명시한다.
- **Q6. `Fold` 펼침 기억 범위** — 종목별(exerciseId) 기억은 종목이 많으면 키가 늘어난다. → `fold:block` 하나(전역)로 시작하고, 종목별 기억은 하지 않는다. 대부분 접어 둔 채 쓰고, 필요할 때만 연다.
- **Q7. PR 금색 글자의 탭 목표** — 한 줄에 「PR …」·「볼륨 PR …」·ⓘ 2개가 들어가면 360px 에서 줄이 넘친다. → 두 조각 사이 간격 8px, 각 조각 높이 ≥ 32px, ⓘ 는 조각 안 오른쪽 아이콘(별도 버튼 아님)으로 넣고, 길게 누르기 대신 **ⓘ 를 누르면 기록으로** 간다(보고서 D3 의 「길게 눌러」는 쓰지 않는다 — 발견하기 어려움). 줄이 넘치면 두 줄로 감싼다.
- **Q8. kg/lb 를 표 머리로 옮길 때 폭** — 표 머리 「무게」 칸은 `flex-1` 이지만 360px 에서 「한쪽 kg│lb」 토글과 라벨이 같이 들어가면 약 84px 가 필요하다. → `UnitToggle compact` 는 라벨을 빼고 「kg│lb」만 둔다(한쪽 입력이면 칸 라벨 「한쪽」을 위에 caption 으로). 360 좌표 e2e 로 겹침을 확인한다.

- **L2.** F6 정렬에서 「EZ바」를 뒤로 보내면 사용자가 「이지바」로 기억하는 경우가 있다. → 검색 별칭이 이미 있으므로 정렬만 바꾼다.
