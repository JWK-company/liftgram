**밟은 것**: 계약 enum을 그대로 정규화에 넣어 태그가 전부 걸러졌다 → enum→도메인 변환을 앞에. 설정은 **카드가 직접 읽는다**(화면 하나를 빠뜨리면 그 화면만 고지 규칙이 달라진다).

## 발견·프로그램·종목 폼 (2026-08-03)
- 발견: `ListExplore`·`SuggestedUsers`·`Search` · `/explore` 한 화면이 두 모드. **발견은 부분 실패 관용**, **검색은 묶어서** 실패(부분 결과가 성공처럼 보이면 "없다"와 "못 찾았다"가 구분 안 된다)
- 인기 = 좋아요 순(댓글 수 정렬 금지 — 내려간 댓글까지 세어 오염) · 추천 = **친구의 친구 먼저**, 모자라면 팔로워 순
- 종목 폼 — **이름만으로** 만든다 · 프로그램 `/program` — 규칙은 core에 있었다·**미리보기에서 교체·제외 후 채택** · 검증 = Go 5건·e2e 4종

## 피드백 탭 · 주변 헬스장 (2026-08-03)
- **순서를 바꿨다**: 코칭의 리포트·처방이 둘 다 `SyncRecord`(동기 엔진 저장소)를 읽는다 → 지금 만들면 반쪽. **코칭은 동기 엔진 뒤로** 미루고 독립적인 둘을 먼저 했다
- 피드백: **저장소 없이** PLM 아이디어보드에 얹는다(상태는 PLM 소유) · 분류·제출자는 본문 최후미 **기계 마커**로 왕복 — **마커가 신뢰 경계**(① 마지막 것만 믿고 ② 앞에 푸터 필수 — 없으면 남의 uid로 위장된다)
- 헬스장(SRS-035): 서버 없음 — `lib/gymSearch.ts`(위치+Overpass 미러 2) · 랭킹은 core에 있었다 · **브라우저에서 직접** 부른다(서버 경유면 우리 IP 하나로 공용 한도에 먼저 걸린다)
- **밟은 것**: `Permissions-Policy`가 `geolocation=()`이라 **우리가 우리 위치 기능을 막고 있었다** — 허용해도 "정책 차단"이라 권한 거부와 구분 불가. `geolocation=(self)`로 열었다(e2e가 아니었으면 못 봤다)
- 프로필 단위 flake: `aria-pressed`는 **메모리 관측값**이라 flush보다 먼저 뒤집힌다 → 버튼이 다시 enabled 되는 시점을 함께 기다린다 · 검증 = Go 10건·e2e 9종·가짜 보드 왕복 실증

## 서버 동기 엔진 (2026-08-03)
- 계약 `proto/sync/v1`(Pull·Push) · 스키마 `0011` · 규칙은 **core 소유**(`sync/syncEngine.ts`·`syncOwner.ts`), 말하는 방법만 `frontend/lib/syncTransport.ts`가 꽂는다 → 저장소 5곳의 `scheduleSync()`를 손대지 않았다
- **레코드는 JSON 문자열** — 서버는 속을 모른다(스키마 권위=클라이언트). `Struct`면 숫자가 double이 되어 "받은 그대로"가 깨진다
- **커서를 1초 물려 준다**: 상한을 그대로 주면 *커밋이 늦은* 레코드가 영영 누락된다(t0 쓰고 t2 커밋 → 다음 pull은 t1 뒤만 묻는다). 다시 받는 비용 < 잃는 비용. 커서·`updated_at`은 **같은 시계**(DB `now()`)·미래 커서는 0으로
- `_status`·`_changed`는 **양쪽에서** 걷어낸다 — 서버에 남으면 다음 pull에서 되돌아와 동기가 죽는다(화면엔 "서버 연결 실패"로만 보인다). 계정 경계: 다른 계정 로그인 시 **로컬을 비우고** 카탈로그만 재시드
- **밟은 것 2건**: ① 동기 결과를 flush하지 않으면 직후 화면 이동에 사라지는데 **커서는 전진해 서버가 다시 안 보낸다**(조용한 유실) → `synchronize()` 뒤 flush ② 주기 폴링을 뺐더니 열어 둔 기기가 남의 변경을 영영 못 받았다 → app과 같은 120초 복원
- 검증: Go 19건(커서·위조·한계) · e2e 6종(**브라우저 둘 = 기기 둘**) · 자동 동기는 **서버에 직접 물어** 확인

## 코칭 — 마지막 화면 (2026-08-03)
- 계약 `proto/coaching/v1`(RPC 8)·스키마 `0012` · **회원 기록은 복사하지 않는다**(`sync_records`를 그 자리에서 집계 — 복사하면 해지 뒤에도 남는다)
- **동의는 통보가 아니다**: 요청은 어느 쪽이든 걸지만 **요청한 쪽은 수락할 수 없다**(없으면 트레이너가 회원을 지정·자가 수락해 회원 모르게 기록을 연다) · 범위 셋뿐이고 **신체 정보는 목록에 없다** · 깨진 범위 설정은 **전부 차단**으로 읽는다
- **열람도 감사에 남고 회원이 읽는다** — 감시받는 쪽이 감시 기록을 못 보면 신뢰 장치가 아니다. 감사 저장 실패가 이미 일어난 수락·해지를 되돌리지는 않는다
- 리포트는 **사실만**(ADR-028): 워밍업·실패·미체크 세트는 볼륨에서 뺀다(부풀린 숫자로 무게를 올리면 다치는 쪽은 회원)
- 처방은 회원 레코드의 **한 필드만** 건드린다(+세트 수) · 서버가 다시 정리(앱을 안 거치는 경로가 있다) · 편집 UI는 루틴 편집기와 **같은 것** · 검증 = Go 25건·e2e 5종(기기 둘)
- **밟은 것 2건**: ① 웹의 코칭 의향 토글이 로컬에만 적혀 **아무에게도 안 보였다** → 서버 프로필 이중 기록 복원 ② 화면 여럿이 동시에 뜰 때 401이 몰려 **refresh 회전이 서로를 무효화**(목록이 "불러오지 못했어요") → 보내기 전에 세션을 되살리도록 `session.ts` 수정(단일 비행)

## 마무리 묶음 (2026-08-04)
- **브랜치 분리**: `feat/web-stack-tarae` — 층별 8커밋(골격·계약·DB·백엔드·core·화면·e2e·거버넌스). 각 커밋은 이식의 층을 나눈 것이라 **HEAD에서만 빌드된다**
- 유산소 세트행(SRS-030): 무게·횟수 대신 **종목이 정한 지표**(러닝머신=시간·거리·경사·속도·줄넘기=시간만) · 저장 초·미터/입력 분·km(변환은 도메인 한 곳) · 볼륨 칩 대신 총 시간·거리
- 온보딩(SRS-045): 두 장·전부 건너뛸 수 있다 · 본 표시는 localStorage(서버면 로그인 전엔 모르고 로컬 DB면 계정 바꿀 때 지워진다) · **e2e 기본을 "이미 본"으로** 두지 않으면 전 테스트가 안내부터 닫아야 한다 · 저장을 **기다린 뒤** 닫는다(닫자마자 이동하면 사라진다)
- **refresh → httpOnly 쿠키**: 값이 브라우저 스크립트에 한 번도 나타나지 않는다(XSS가 나도 15분짜리 access뿐). 갱신·폐기는 `/api/session*` 라우트가 대신한다 · CSRF는 `SameSite=Strict`+커스텀 헤더 두 겹 · 옛 localStorage 토큰은 **한 번 이행**(없으면 기존 로그인이 전부 풀린다)
- 사진 메시지: 계약·서버는 이미 있었고 **보내는 절반만** 없었다 — 올린 뒤 보낸다(실패하면 아예 안 보낸다·빈 말풍선 방지)
- **전체 e2e 86종 중 81통과·2 부하 flake(단독·소그룹 실행은 전부 통과)·3 env 게이트 skip**. 전체 실행이 17분으로 늘었고 CPU 10%(=대기) — e2e DB에 계정·동기행 5만이 쌓인 탓으로 보인다. 관찰: **시드 카탈로그 336종이 계정마다 서버로 올라간다**(app과 같은 동작이나 규모가 커지면 낭비 — 별도 판단 필요)
